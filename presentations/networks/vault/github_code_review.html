מהי סקירת קוד?

חבר צוות בוחן שינוי בקוד לפני שילובו בענף היעד. המטרה: נכונות, אמינות, קריאות ולמידה הדדית.

Author — מפתח

מסביר את השינוי, מציג בדיקות ומגיב למשוב.

Reviewer — סוקר

בודק את השינוי, שואל שאלות ומציע שיפורים.

סימולטור החלטת סוקר

def stop(self):
    self.sock.shutdown(2)

הקוד עובד, אך המספר 2 אינו ברור. אין דרישה המחייבת תיקון סגנון לפני שילוב. מהי תגובה מתאימה?

פתרון והסברהקבוע מבטא את כוונת הקוד. זהו שיפור קריאות ולא בהכרח ליקוי חוסם.
שקף 12 / 15

אתגר יישומי — סגירת שרת

with self.lock:
    for handler in self.handlers:
        handler.stop()
        handler.join()

כל Handler צריך את אותו lock כדי להסיר את עצמו בסיום. כתבו הערת סקירה והציעו תיקון.

פתרון מוצע
with self.lock:
    handlers = list(self.handlers)
for handler in handlers:
    handler.stop()
for handler in handlers:
    handler.join()
המתנה מחוץ למנעול מונעת את ה-Deadlock המתואר. ניתן לשקול timeout ובדיקת is_alive. בדקו סגירה עם כמה לקוחות.
