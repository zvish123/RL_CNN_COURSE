האם כל קוד רשאי לשנות כל תכונה?

דמיינו מחלקה המייצגת מטוס. מה יקרה אם כל חלק בתוכנית יוכל לקבוע מהירות שלילית?

plane.speed = -500 print(plane.speed)

הבעיה

גישה חופשית למידע עלולה לאפשר מצב לא תקין של האובייקט.

השאלה שנחקור

איך שומרים על הנתונים ובכל זאת משתמשים בתחביר נוח כמו plane.speed?

1. תכונות רגילות: גישה ישירה

class CrazyPlane: def __init__(self, speed): self.speed = speed plane = CrazyPlane(100) plane.speed = -500 # חוקי בפייתון!

התכונה speed נגישה לשינוי מבחוץ. שום דבר אינו בודק את הערך החדש.

מטרת התכנון: לשמור על תקינות מצב האובייקט, בלי לסרבל את אופן השימוש בו.

2. שלוש צורות נפוצות לשמות תכונות

self.speed

תכונה ציבורית לפי המוסכמה. מיועדת לשימוש חיצוני.

self._speed

קו תחתון יחיד: מוסכמה שפירושה לשימוש פנימי. אין מניעה טכנית לגשת.

self.__speed

שני קווים תחתונים בתחילת השם: מופעל מנגנון Name Mangling.

__init__

שני קווים גם בהתחלה וגם בסוף: שם מיוחד של פייתון; לא אותו מנגנון.

3. האם __speed באמת פרטי?

class CrazyPlane: def __init__(self): self.__speed = 100 plane = CrazyPlane() print(plane.__speed)

מה תהיה התוצאה?

4. מאחורי הקלעים: Name Mangling

פייתון משנה שם מהצורה __speed לשם הכולל את שם המחלקה:

plane._CrazyPlane__speed # 100

זה לא מנגנון אבטחה ולא פרטיות מוחלטת! ניתן עדיין לגשת לערך דרך השם המומר. המנגנון נועד בעיקר למנוע התנגשויות שמות במחלקות יורשות.

לכן עדיף לומר: תכונה עם Name Mangling, ולא להבטיח שהיא מוגנת.

להגנה על מידע סודי דרושים מנגנוני אבטחה והרשאות — לא רק קידומת __.

5. כיצד נותנים גישה מבוקרת?

אפשר להגדיר מתודה שמחזירה ערך, אבל פייתון מאפשרת ממשק נוח יותר: @property.

גישה באמצעות מתודה

plane.get_speed()

גישה באמצעות property

plane.speed

בשני המקרים אפשר להריץ קוד בזמן הקריאה. ההבדל הוא בממשק שהמחלקה מציגה למשתמש.

6. @property: קריאה כמו תכונה

class CrazyPlane: def __init__(self, speed): self.__speed = speed @property def speed(self): return self.__speed plane = CrazyPlane(100) print(plane.speed) # 100

שימו לב: לא כותבים plane.speed(). ההפעלה נראית כמו קריאת תכונה.

תתרחש AttributeError, כי לא הוגדר setter. זו תכונה לקריאה בלבד באמצעות הממשק הציבורי הרגיל (לא מנגנון אבטחה).

7. @speed.setter: אימות לפני שינוי

class CrazyPlane: def __init__(self, speed): self.speed = speed @property def speed(self): return self.__speed @speed.setter def speed(self, value): if value < 0: raise ValueError("Speed must be non-negative") self.__speed = value

ההשמה self.speed = speed בבנאי מפעילה את ה־setter, ולכן גם הערך ההתחלתי נבדק.

8. סימולציה: קביעת מהירות למטוס

הכניסו מהירות ונסו לעדכן את האובייקט. המדמה מפעיל את כלל האימות של ה־setter.

מצב האובייקט

plane.speed = 100

מהירות התחלתית: 100

ה־setter יכול לדחות שינוי, כך שהאובייקט נשאר במצב תקין.

9. ניבוי קוד: מה יודפס?

p = CrazyPlane(100) p.speed = 250 print(p.speed) try: p.speed = -5 except ValueError: pass print(p.speed)

איזה זוג ערכים יודפס?

10. טעות נפוצה: רקורסיה אינסופית

@property def speed(self): return self.speed # בעייתי! @speed.setter def speed(self, value): self.speed = value # בעייתי!

מדוע זה לא עובד?

ה־getter קורא לעצמו וה־setter מפעיל שוב את עצמו. בסופו של דבר מתקבלת RecursionError.

@property def speed(self): return self.__speed @speed.setter def speed(self, value): self.__speed = value

משתמשים בשם נפרד לאחסון הפנימי. בקוד מלא יש להוסיף בדיקת תקינות ל־setter.

11. שימוש נוסף: תכונה מחושבת

class Rectangle: def __init__(self, width, height): self.width = width self.height = height @property def area(self): return self.width * self.height r = Rectangle(4, 5) print(r.area) # 20 r.width = 6 print(r.area) # 30

ל־area אין צורך בשדה אחסון נפרד. הערך מחושב כאשר ניגשים לתכונה.

12. ומה הקשר ל־OOP ולתכנון מחלקות?

כימוס (Encapsulation)

המחלקה מרכזת את הנתונים ואת הכללים לשינויים בהם.

ממשק ברור

קוד חיצוני עובד עם plane.speed, בלי לדעת כיצד הערך נשמר.

אימות

אפשר לדרוש ערכים חוקיים ולהציף חריגה כשיש שגיאה.

שיקול תכנוני

לא כל שדה צריך property: לעיתים תכונה ציבורית פשוטה מספיקה.

13. אתגר: תקנו את המחלקה

class Position: def __init__(self, x): self.__x = x @property def x(self): return self.__x @x.setter def x(self, value): self.__x = value

דרישה: x חייב להיות מספר שלם בין 0 ל־9. אילו שני מקומות בקוד צריך לבדוק?

class Position: def __init__(self, x): self.x = x # אימות גם בבנאי @property def x(self): return self.__x @x.setter def x(self, value): if type(value) is not int or not 0 <= value <= 9: raise ValueError("x must be an integer from 0 to 9") self.__x = value

הבדיקה type(value) is int מונעת גם קבלת True, שהוא תת־טיפוס של int בפייתון.

14. שאלת סיכום: לבחור נכון

מהי הטענה המדויקת ביותר?

כרטיס יציאה

מה לקחתם מהשיעור?

1. מדוע נעדיף לעיתים self.__speed על self.speed לאחסון פנימי?

2. מה ההבדל בין @property לבין @speed.setter?

3. כיצד נוודא שערך לא תקין לא נכנס לאובייקט כבר בבנאי?

1. להפרדת הייצוג הפנימי ולמניעת התנגשויות שמות — לא כהגנת אבטחה.

2. הראשון מגדיר קריאה דמוית תכונה; השני מגדיר התנהגות בהשמה.

3. נבצע בבנאי השמה דרך ה־property, למשל self.speed = speed, כדי להפעיל את האימות.

העיקרון: להגן על תקינות האובייקט באמצעות ממשק מתוכנן, לא באמצעות שם בלבד.
