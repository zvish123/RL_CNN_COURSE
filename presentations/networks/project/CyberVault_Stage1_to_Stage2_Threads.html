ניסוי: שני לקוחות מתחברים

שאלת חקר: לקוח A מחובר ולא שולח הודעות. מה יקרה כאשר לקוח B ינסה להתחבר ולשלוח PING?

לקוח A

מחובר · ממתין לקלט

השרת נמצא בתוך recv().

לקוח B

מבקש שירות

ייתכן שהחיבור יושלם, אבל מי יקרא את הבקשה?

השרת לא חזר ל־accept(), ולכן היישום לא מטפל בלקוח B. השלמת connect() אינה הוכחה לכך שהשרת כבר מטפל בלקוח.

היכן בדיוק הבעיה בקוד?

def start(self): client_socket, address = self.__server.accept() self.__handle_client(client_socket, address) self.__server.close()

סמנו לעצמכם: איזו שורה מונעת קבלת לקוח חדש בזמן הטיפול בלקוח הראשון?

הבעיה היא רצף הפעולות: קריאת accept() אחת בלבד, ולאחריה __handle_client() חוסמת. אין חזרה ל־accept(); לבסוף שקע השרת נסגר.

הקוד מוצג כשלד רעיוני של התנהגות השרת המתוארת בדף העבודה, ולא כהעתקה של קובץ המקור.

מהי פעולה חוסמת (Blocking)?

accept()

ממתינה לחיבור חדש כאשר אין חיבור מוכן.

recv()

ממתינה לנתונים כאשר אין נתונים זמינים והחיבור עדיין פתוח.
פעולה חוסמת עוצרת את התהליכון שמבצע אותה — לא בהכרח את כל התהליך.

שאלה: לקוח מחובר ולא שולח הודעות. מה יקרה לתהליכון שממתין ב־recv()?

האם לולאה סביב accept מספיקה?

while True: client_socket, address = server.accept() handle_client(client_socket, address)

האם הקוד הזה מטפל בלקוחות במקביל?

לולאה משפרת את היכולת לטפל בלקוחות ברצף; כדי לטפל בהם בחופף נדרש מנגנון נוסף.

הפתרון: Threads

Thread (תהליכון) הוא נתיב ביצוע בתוך תהליך. אפשר להפעיל כמה תהליכונים כדי שמשימות חוסמות לא יעכבו זו את זו.

ב־Python, Threads שימושיים במיוחד לעבודה עם I/O כמו תקשורת רשת. הם אינם מבטיחים האצה של חישובי CPU.

הכירו את threading.Thread

import threading import time def task(name): for i in range(3): print(name, i) time.sleep(1) t1 = threading.Thread(target=task, args=("A",)) t2 = threading.Thread(target=task, args=("B",)) t1.start() t2.start() t1.join() t2.join() print("Finished")

איך נראה שרת עם Thread לכל לקוח?

import threading while running: client_socket, address = server.accept() worker = threading.Thread( target=handle_client, args=(client_socket, address) ) worker.start()
השרת הראשי חוזר מיד ל־accept(); התהליכון החדש מטפל בלקוח.

זהו שלד לימודי: ביישום מלא נוסיף טיפול בשגיאות, ניהול תהליכונים, סגירת שקעים ועצירה מסודרת.

NetworkServer

אחראי ל־accept, ליצירת מטפלים ולניהול חיי השרת.

ClientHandler

אחראי ללולאת קבלת הבקשות, עיבודן, שליחת תגובות וסגירת חיבור הלקוח.

שאלת תכנון: לאיזו מחלקה שייכת הפעולה שמטפלת בפקודת PING?

לוגיקת עיבוד הפקודה יכולה להיות פעולה של ClientHandler או רכיב לוגיקה נפרד. העיקר ש־NetworkServer לא יישא באחריות לכל לולאות התקשורת עם הלקוחות.

מידע משותף

שני תהליכונים מעדכנים יחד רשימת לקוחות או מונה.

סגירת השרת

מה עושים אם יש עדיין לקוחות מחוברים?

ניתוק פתאומי

לקוח נסגר באמצע קבלת הודעה.

מספר תהליכונים

לכל לקוח תהליכון משלו — אך מספר בלתי מוגבל צורך משאבים.
Lock להגנה על מצב משותף; join() להמתנה לסיום; try/finally לסגירת משאבים; ומנגנון עצירה וניהול חיבורים. בשלבים מתקדמים אפשר ללמוד גם ThreadPool או select.
