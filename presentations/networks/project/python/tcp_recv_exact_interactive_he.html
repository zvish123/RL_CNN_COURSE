01 | היכרות

מהו TCP?

✅ אמינות

TCP מספק העברה אמינה כאשר החיבור פועל בהצלחה, או מאותת על כשל.

↔️ סדר

הבתים נמסרים ליישום המקבל באותו סדר שבו נשלחו.

〰️ זרם בתים

TCP אינו שומר את גבולות ההודעות שיצרה התוכנה.

הודעה בתוכנה ≠ חבילת רשת ≠ קריאה בודדת ל־recv().
02 | הטעות הנפוצה

שלחנו 10 בתים. מה נקבל?

sendall(b"HELLOWORLD")

אפשרות א׳

recv(10) → b"HELLOWORLD"

כל 10 הבתים בקריאה אחת.

אפשרות ב׳

recv(10) → b"HEL"

רק 3 בתים בקריאה הראשונה.

שתי האפשרויות תקינות! המספר ב־recv(10) הוא גבול עליון, לא הבטחה לקבלת 10 בתים.
03 | מגלים את הכלל

מה recv(n) באמת עושה?

בסוקט TCP חוסם, היא ממתינה למידע — אך עשויה להחזיר פחות מ־n בתים.

החזרה אפשריתפירוש
b"HELLOWORLD"התקבלו 10 בתים
b"HEL"התקבלו רק 3 בתים
b"H"התקבל בית אחד
b""סוף זרם הקלט — הצד המרוחק סיים לשלוח

הערה: הסבר זה מתייחס לסוקט TCP חוסם רגיל. Timeout ושגיאות דורשים טיפול נוסף.

04 | אתגר כיתתי

מה הבעיה בקוד?

def receive_ten(sock):
    data = sock.recv(10)
    return data

הפונקציה מבטיחה להחזיר בדיוק 10 בתים?

לא!

ייתכן ש־recv(10) תחזיר 2 או 5 בתים בלבד. הקוד אינו בודק אם התקבל האורך הדרוש ואינו משלים את החסר.

05 | הפתרון

הלולאה של __recv_exact

def __recv_exact(sock, n):
    buf = b""
    while len(buf) < n:
        chunk = sock.recv(n - len(buf))
        if not chunk:
            return None
        buf += chunk
    return buf
buf

07 | חשיבה על הקוד

למה לא לקרוא תמיד recv(10)?

היישום צריך 10 בתים, וכבר קיבל 7.

ניסיון שגוי

chunk = sock.recv(10)

עשוי לקרוא גם בתים של ההודעה הבאה.

הניסיון הנכון

chunk = sock.recv(10 - 7)

מבקש לכל היותר את 3 הבתים החסרים.

המטרה: לא לקרוא מעבר לגבול של ההודעה שאנחנו אוספים.
08 | מצב קצה

ומה אם הלקוח סגר את החיבור?

chunk = sock.recv(n - len(buf))
if not chunk:
    return None

b"ABC"

הגיע מידע, אפשר לצרף אותו ל־buf.

b""

סוף זרם הקלט. לא יגיעו עוד בתים בחלק זה של החיבור, ולכן מוחזר None.

הפונקציה מחזירה None ולא את ששת הבתים החלקיים — כי החוזה שלה הוא להחזיר בדיוק 10 בתים או לסמן שלא הצליחה להשלים את הקריאה.
09 | התמונה הגדולה

איך יודעים היכן הודעה מסתיימת?

TCP לא מסמן גבולות הודעות. לכן פרוטוקול הכספת מוסיף כותרת אורך (Length Prefix).

Header

0000000A

4 בתים: המספר 10 ב־Big-Endian.

Body

ECHO|HELLO

10 בתים של תוכן, בקידוד UTF-8.

Header אומר כמה לקרוא. גוף ההודעה אומר מה נשלח.
10 | מתוך protocol.py

header = Protocol.__recv_exact(sock, 4)
if header is None:
    return None

length = int.from_bytes(header, "big")
data = Protocol.__recv_exact(sock, length)
if data is None:
    return None

return ProtocolMessage.from_bytes(data)
① Header

קוראים בדיוק 4 בתים.

② Length

מפרשים את האורך כמספר שלם.

③ Body

קוראים בדיוק את כמות הבתים שצוינה.

11 | הדגמת פרוטוקול

בונים כותרת לפי אורך המידע

בחרו תוכן הודעה באנגלית (ASCII), ולחצו על ״בנה הודעה״.

הדוגמה מוגבלת כאן לתווי ASCII כדי שאורך המחרוזת יהיה זהה למספר הבתים. בטקסט עברי UTF-8 משתמשים ב־len(text.encode('utf-8')).

12 | אבטחה ויציבות

מה עוד צריך לבדוק במערכת אמיתית?

⏳ Timeout

לקוח שלא שולח את שאר המידע עלול לגרום לקריאה להמתין זמן רב.

📦 הגבלת אורך

לקוח יכול לפרסם גודל עצום ב־Header. יש להגדיר אורך מרבי מעשי.

⚠️ טיפול בשגיאות

ייתכנו חריגות תקשורת, ניתוקים והודעות לא תקינות.

בקוד הפרויקט נבדק בעת שליחה שהאורך מתאים ל־4 בתים; זה אינו מחליף מגבלת אורך מעשית בצד המקבל.

14 | אתגר סיום

הסבירו את הקוד במילים שלכם

while len(buf) < n:
    chunk = sock.recv(n - len(buf))
    if not chunk:
        return None
    buf += chunk

שאלו אחד את השני: מהו תנאי העצירה? למה מחסרים את len(buf)? מתי מוחזר None?

הלולאה נמשכת כל עוד חסרים בתים. בכל איטרציה מבקשים רק את מספר הבתים שחסר. אם הצד השני סיים לשלוח לפני השלמה, מוחזר None; אחרת, כשנצברו בדיוק n בתים, הלולאה מסתיימת.

משפט לזכור: recv(n) = עד n בתים; recv_exact(n) = בדיוק n בתים, או כישלון.
