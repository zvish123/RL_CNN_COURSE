Command Design Pattern

כיתה י״ב · Python · כספת קבצים · למידה ותרגול אינטראקטיבי

מבוא: מהי תבנית העיצוב Command?

Command היא תבנית עיצוב התנהגותית (Behavioral Design Pattern) ההופכת בקשה לביצוע פעולה לאובייקט. האובייקט שומר את הנתונים הדרושים לביצוע הפעולה ומספק מתודה אחידה execute().

במקום שמנהל הבקשות יקרא ישירות למתודות שונות של הכספת, הוא מקבל אובייקט פקודה ומפעיל אותו. כך מפרידים בין יצירת הבקשה, ניהול הביצוע וביצוע הפעולה בפועל.

ללא Command

vault.delete_file("a.txt")

קוד הקורא תלוי ישירות בפעולת המחיקה.

עם Command

cmd = DeleteFileCommand(vault, "a.txt")
manager.run(cmd)

המנהל מפעיל כל פקודה דרך ממשק משותף.

מתי כדאי להשתמש בתבנית?

  • כשיש סוגי פעולות רבים שצריך להפעיל באותו מנגנון.
  • כשנדרש תור פקודות, תזמון או ביצוע מאוחר.
  • כשרוצים היסטוריה, רישום פעולות או ניטור במקום מרכזי.
  • כשיש צורך ב־Undo עבור פעולות שניתן לבטל (נדרש מימוש ייעודי).
  • כשמוסיפים פעולות חדשות לעיתים קרובות ורוצים להימנע משינוי ה־Invoker.

מתי לא בהכרח? אם מדובר בקריאה אחת ופשוטה ללא צורך בניהול פקודות, התבנית עלולה להוסיף מחלקות ומורכבות מיותרת.

מבנה UML – הסבר המרכיבים והקשרים

תרשים UML כללי של חמשת תפקידי תבנית Command: Client יוצר ConcreteCommand ומוסר אותו ל־Invoker; ה־Invoker מפעיל את ממשק Command; ה־ConcreteCommand מממש את הממשק ומפעיל פעולה ב־Receiver. המתודה undo() אופציונלית ונלמדת במשימת ההרחבה.

בדוגמת הכספת כל תפקיד ממופה למחלקה קונקרטית, כמפורט בטבלה:

מרכיבתפקידבדוגמת הכספת
Commandמחלקה מופשטת המגדירה חוזה execute()כל פקודה חייבת לממש את הפעולה
ConcreteCommandשומרת פרמטרים ואת ה־Receiver; מממשת את execute()DeleteFileCommand
Invokerמפעיל פקודות דרך הממשק, בלי לדעת איך הן מבוצעותCommandManager
Receiverמכיל את הלוגיקה העסקית של הפעולהVaultService
Clientיוצר פקודה ומעביר לה את הפרמטרים ואת ה־Receiverקוד main או RequestHandler

סימוני UML: משולש חלול לכיוון מחלקת האב = ירושה; קו מקווקו עם חץ = תלות; קו רציף = קשר שימוש. שמות המחלקות ממורכזים, ואילו שמות התכונות והמתודות מוצמדים לשמאל בתוך המלבן ונכתבים משמאל לימין (LTR).

זרימת פעולה: Client יוצר DeleteFileCommand → CommandManager.run() קורא execute() → הפקודה מפעילה VaultService.delete_file().

1. הבעיה: קוד שהולך וגדל

מערכת הכספת מאפשרת מחיקה והעלאה. בתחילה, ממשק המשתמש קורא ישירות לפונקציות:

if action == "DELETE":
    vault.delete_file(filename)
elif action == "UPLOAD":
    vault.upload_file(filename)

מה יקרה כשנרצה להוסיף שינוי שם, תיעוד פעולות, תור פקודות והתראות? במקום לקשור את מנהל הבקשות לכל פעולה, נייצג כל בקשה כאובייקט.

Command היא תבנית התנהגותית המפרידה בין מי שמבקש פעולה, מי שמפעיל אותה, ומי שמבצע אותה בפועל.

2. תפקידי התבנית

תפקידבכספתאחריות
ClientRequestHandler / mainיוצר פקודות
CommandCommand (ABC)חוזה execute()
ConcreteCommandDeleteFileCommandשומר פרמטרים ומפעיל Receiver
InvokerCommandManagerמפעיל כל פקודה באותה דרך
ReceiverVaultServiceמבצע פעולות קבצים

תרשים מחלקות: משולש חלול מסמן ירושה; קו מקווקו מסמן תלות. CommandManager תלוי בממשק Command, לא במחלקת המחיקה המסוימת. גם UploadFileCommand יורשת מ־Command ומממשת execute(), בדיוק כמו DeleteFileCommand.

3. מימוש בסיסי בפייתון

from abc import ABC, abstractmethod

class Command(ABC):
    @abstractmethod
    def execute(self):
        pass

class VaultService:
    def __init__(self):
        self.files = ["a.txt", "b.txt", "c.txt"]

    def delete_file(self, filename):
        if filename not in self.files:
            raise FileNotFoundError(filename)
        self.files.remove(filename)

    def upload_file(self, filename):
        if filename in self.files:
            raise FileExistsError(filename)
        self.files.append(filename)

class DeleteFileCommand(Command):
    def __init__(self, vault, filename):
        self.vault = vault
        self.filename = filename

    def execute(self):
        self.vault.delete_file(self.filename)

class UploadFileCommand(Command):
    def __init__(self, vault, filename):
        self.vault = vault
        self.filename = filename

    def execute(self):
        self.vault.upload_file(self.filename)

class CommandManager:
    def run(self, command):
        command.execute()

vault = VaultService()
manager = CommandManager()
manager.run(DeleteFileCommand(vault, "a.txt"))
manager.run(UploadFileCommand(vault, "new.txt"))
print(vault.files)  # ['b.txt', 'c.txt', 'new.txt']

שימו לב: שתי הפקודות מממשות את אותו ממשק. מנהל הפקודות אינו יודע מהי מחיקה או העלאה. הוא מכיר רק execute().

4. מעבדה אינטראקטיבית

הדמיה בדפדפן של עקרון Command (קוד הלמידה עצמו בפייתון). הפעולות כאן אינן נוגעות לקבצים אמיתיים.

קבצים בכספת: 

מה משתנה ב־CommandManager כאשר מוסיפים פקודה חדשה עם execute()? שום דבר, כל עוד לא מכניסים אליו לוגיקה שתלויה בסוג הפקודה.


5. משימת תלמידים – הוספת יכולת חדשה (15 דקות)
אירוע: משתמש מבקש לשנות שם של קובץ בכספת. הצוות צריך להוסיף יכולת Rename בלי לשנות את המנגנון שמפעיל פקודות.
  1. הוסיפו ל־VaultService מתודה rename_file(old_name, new_name). יש לוודא שהמקור קיים ושהיעד אינו קיים.
  2. צרו מחלקה RenameFileCommand(Command) עם הפרמטרים vault, old_name, new_name.
  3. ממשו execute() שקוראת למתודה של הכספת.
  4. הפעילו את הפקודה באמצעות manager.run(...) והדפיסו את רשימת הקבצים.
  5. השוו את CommandManager לפני ואחרי השינוי. האם נדרש שינוי בקוד שלו?
רמז למימוש
class RenameFileCommand(Command):
    def __init__(self, vault, old_name, new_name):
        self.vault = vault
        self.old_name = old_name
        self.new_name = new_name

    def execute(self):
        self.vault.rename_file(self.old_name, self.new_name)
פתרון מלא – לפתוח לאחר ניסיון עצמאי
def rename_file(self, old_name, new_name):
    if old_name not in self.files:
        raise FileNotFoundError(old_name)
    if new_name in self.files:
        raise FileExistsError(new_name)
    self.files[self.files.index(old_name)] = new_name

class RenameFileCommand(Command):
    def __init__(self, vault, old_name, new_name):
        self.vault = vault
        self.old_name = old_name
        self.new_name = new_name

    def execute(self):
        self.vault.rename_file(self.old_name, self.new_name)

manager.run(RenameFileCommand(vault, "b.txt", "final.txt"))
יש להוסיף את המתודה הראשונה בתוך המחלקה VaultService.


6. משימה – הרחבת יכולת קיימת (15 דקות)
דרישה חדשה: מנהל האבטחה רוצה לקבל התראה אחרי 3 מחיקות מוצלחות של אותו משתמש. לא סופרים העלאות, שינויי שם או מחיקות שנכשלו.
  1. הוסיפו ל־DeleteFileCommand פרמטר user.
  2. הוסיפו ל־CommandManager מילון delete_counts.
  3. לאחר execute() מוצלח, עדכנו את המונה עבור פקודת מחיקה והציגו התראה כשהמונה מגיע ל־3.
  4. בדקו שתי מחיקות של Alice, מחיקה אחת של Bob ומחיקה שלישית של Alice.
  5. בדקו ניסיון מחיקת קובץ שאינו קיים: האם המונה משתנה?
שאלת תכנון: הפתרון הפשוט משתמש ב־isinstance(command, DeleteFileCommand). אילו מחלקות השתנו? האם הרחבה עתידית לניטור הורדות תחייב שינוי נוסף ב־CommandManager?
פתרון בסיסי להרחבה
class CommandManager:
    def __init__(self):
        self.delete_counts = {}
        self.alerted = set()

    def run(self, command):
        command.execute()  # כישלון מונע ספירה
        if isinstance(command, DeleteFileCommand):
            user = command.user
            count = self.delete_counts.get(user, 0) + 1
            self.delete_counts[user] = count
            if count >= 3 and user not in self.alerted:
                print(f"SECURITY ALERT: {user}")
                self.alerted.add(user)
יש לעדכן גם את __init__ של DeleteFileCommand כך שישמור self.user. זהו פתרון לימודי פשוט, אך הוא יוצר תלות בין המנהל למחלקה קונקרטית.


7. משימת הרחבה – היסטוריית פקודות ו־Undo (20–25 דקות)


סיפור: משתמש מחק בטעות קובץ מהכספת. מנהל המערכת מבקש לשמור היסטוריה של פעולות שהצליחו, ולאפשר לבטל את הפעולה האחרונה.


מטרת המשימה: להרחיב יכולת קיימת של Command בלי לשנות את קוד ההפעלה של כל פקודה בנפרד. במשימה זו Undo פועל על רשימת הקבצים בזיכרון בלבד, ולא על קבצים אמיתיים.


    

  1. הרחבת הממשק: הוסיפו למחלקה המופשטת Command מתודה מופשטת undo(), לצד execute().
    2. 

  2. ביטול מחיקה: במחלקה DeleteFileCommand, שמרו בזמן הביצוע את מיקום הקובץ ברשימה. ב־undo() החזירו את הקובץ למקומו המקורי. הוסיפו ל־VaultService פעולה מתאימה לשחזור, או השתמשו במתודה קיימת בצורה מבוקרת.
    3. 

  3. ביטול העלאה: במחלקה UploadFileCommand, ממשו undo() שמסירה את הקובץ שהועלה בהצלחה.
    4. 

  4. היסטוריה: הוסיפו ל־CommandManager רשימה history. המתודה run(command) תוסיף פקודה להיסטוריה רק לאחר שהביצוע הצליח.
    5. 

  5. ביטול הפעולה האחרונה: הוסיפו למנהל מתודה undo_last() שמבטלת את הפקודה האחרונה שהצליחה, ומסירה אותה מההיסטוריה רק לאחר ביטול מוצלח. אם אין פקודות – הציגו הודעה מתאימה.
    6. 

  6. שימוש ביכולת: צרו שתי פקודות, הפעילו אותן באמצעות manager.run(...), הציגו את מצב הכספת, הפעילו manager.undo_last() והציגו שוב את המצב.
    7.

רמז: ניהול ההיסטוריה
def run(self, command):
    command.execute()       # If this raises, do not append
    self.history.append(command)

def undo_last(self):
    if not self.history:
        print("Nothing to undo")
        return
    command = self.history[-1]
    command.undo()          # If this raises, keep history unchanged
    self.history.pop()
