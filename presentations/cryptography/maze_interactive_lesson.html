חיפוש לרוחב — BFS

Breadth-First Search פירושו חיפוש לרוחב: תחילה בודקים את כל התאים במרחק צעד אחד מההתחלה, אחר כך את כל התאים במרחק שני צעדים, וכן הלאה.

כמו גלים המתפשטים במים. משתמשים בתור (Queue): מי שנכנס ראשון נבדק ראשון (FIFO).

יתרון: במבוך שבו כל צעד שווה, הדרך הראשונה שנמצאת ליעד היא הקצרה ביותר במספר צעדים.

חיפוש לעומק — DFS

Depth-First Search פירושו חיפוש לעומק: בוחרים כיוון וממשיכים בו ככל האפשר. כאשר נתקעים, חוזרים לצומת הקודם ומנסים כיוון אחר.

כמו חוקר שנכנס למסדרון עד סופו ורק אז חוזר. אפשר לממש בעזרת רקורסיה או מחסנית.

יתרון: מתאים לבדיקת קיום דרך ולהדגמת חזרה לאחור; אינו מבטיח את המסלול הקצר ביותר.

זכרו: BFS = קודם השכנים הקרובים; DFS = קודם מתקדמים עמוק בענף אחד.

BFS – חיפוש לרוחב

בודקים קודם תאים במרחק צעד אחד, אחר כך שני צעדים וכן הלאה. משתמשים בתור FIFO.

DFS – חיפוש לעומק

מתקדמים בכיוון אחד ככל האפשר; כשנתקעים, חוזרים אחורה ומנסים חלופה. רקורסיה משתמשת במחסנית הקריאות.

משותף לשניהם: בדיקת גבולות, קירות, ביקורים קודמים ותנאי הצלחה.

בעיה 1: האם אפשר להגיע?

חתימת הפונקציה:

can_reach(maze, start_row, start_col, end_row, end_col) -> bool

פסאודו־קוד

1. הכנס את תא ההתחלה למבנה נתונים של תאים לבדיקה.
2. כל עוד נותרו תאים: בחר תא.
3. אם זה היעד — החזר אמת.
4. הוסף שכנים חוקיים שטרם ביקרנו בהם.
5. אם הסתיימו התאים — החזר שקר.

השאלה המרכזית: איך בוחרים את התא הבא? תור מוביל ל־BFS; מחסנית או רקורסיה מובילות ל־DFS.

BFS ללא רקורסיה — קוד

def can_reach(maze, sr, sc, er, ec):
    if not maze or not maze[0]:
        return False
    rows, cols = len(maze), len(maze[0])
    if not (0 <= sr < rows and 0 <= sc < cols
            and 0 <= er < rows and 0 <= ec < cols):
        return False
    if maze[sr][sc] == 1 or maze[er][ec] == 1:
        return False

    visited = {(sr, sc)}
    queue = [(sr, sc)]
    index = 0
    while index < len(queue):
        row, col = queue[index]
        index += 1
        if (row, col) == (er, ec):
            return True
        for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            nr, nc = row + dr, col + dc
            if (0 <= nr < rows and 0 <= nc < cols
                    and maze[nr][nc] == 0
                    and (nr, nc) not in visited):
                visited.add((nr, nc))
                queue.append((nr, nc))
    return False

index מתקדם לאורך הרשימה, ולכן אין צורך ב־pop(0). לכל תא יש לכל היותר ארבעה שכנים.

משתנים מקומיים בכל איטרציה

row, col — התא שנשלף כעת לבדיקה.

dr, dc — שינוי שורה ועמודה בכיוון הנבדק, למשל (1,0) למטה.

nr, nc — קואורדינטות השכן המועמד, המחושבות מהתא הנוכחי ומהכיוון.

חשוב: מסמנים שכן ב־visited כבר בזמן ההוספה לתור, ולא רק כשהוא נבדק.

בדיקת הבנה: מדוע צריך גם queue וגם visited? — לחצו לתשובה

queue שומר סדר בדיקה; visited מונע הוספת אותו תא יותר מפעם אחת. התור לבדו לא מונע כפילויות.

סימולטור BFS — צעד אחר צעד

ירוק כהה = ביקרנו | כתום = תא נוכחי | אפור = קיר

שימו לב: BFS בודק לפי מרחק, ולא בהכרח מתמיד בכיוון אחד.

DFS רקורסיבי — אסטרטגיה

מקרה בסיס: יציאה מגבולות, קיר או ביקור קודם ← False; הגעה ליעד ← True.

צעד רקורסיבי: סמן את התא, ונסה ארבע קריאות רקורסיביות.

חזרה לאחור: אם כיוון נכשל, נסה את הכיוון הבא. אם כולם נכשלו — החזר False.

return (dfs(row - 1, col) or
        dfs(row + 1, col) or
        dfs(row, col - 1) or
        dfs(row, col + 1))

בגלל or, ברגע שקריאה מחזירה אמת אין צורך לנסות כיוונים נוספים.

DFS רקורסיבי — קוד

def can_reach_recursive(maze, sr, sc, er, ec):
    if not maze or not maze[0]:
        return False
    rows, cols = len(maze), len(maze[0])
    visited = set()

    def dfs(row, col):
        if not (0 <= row < rows and 0 <= col < cols):
            return False
        if maze[row][col] == 1 or (row, col) in visited:
            return False
        if (row, col) == (er, ec):
            return True
        visited.add((row, col))
        return (dfs(row - 1, col) or
                dfs(row + 1, col) or
                dfs(row, col - 1) or
                dfs(row, col + 1))

    return dfs(sr, sc)

בדיקות גבול מתבצעות לפני גישה למטריצה. סימון visited מונע לולאות אינסופיות.

DFS • קריאה רקורסיבית

כיצד המשתנים פועלים בזמן הרקורסיה?

הקוד שמקדם את החיפוש

visited.add((row, col))
return (
    dfs(row - 1, col) or  # למעלה
    dfs(row + 1, col) or  # למטה
    dfs(row, col - 1) or  # שמאלה
    dfs(row, col + 1)     # ימינה
)

בכל קריאה הערכים row, col שונים, אך visited היא אותה קבוצה משותפת.

דוגמת רצף קריאות

dfs(0,0) → dfs(0,1) → dfs(1,1) → ...

אם הקריאה מגיעה לקיר או לתא שכבר ביקרנו בו, היא מחזירה False.

אם היא מגיעה ליעד, היא מחזירה True; בגלל or גם הקריאות הקודמות מחזירות הצלחה.

בדיקת הבנה: מדוע לא יוצרים visited חדשה בתוך dfs? — לחצו לתשובה

כי אז כל קריאה תשכח אילו תאים נבדקו בקריאות אחרות, ועלולים להיווצר ביקורים חוזרים ומעגלים. לכן visited מוגדרת בפונקציה החיצונית ומשותפת לכל הקריאות.

דיוק חשוב: ב־DFS שמחזיר רק True/False לא צריך להסיר תאים מ־visited כשחוזרים אחורה. בשמירת מסלול מסירים מ־path, לא מ־visited.

סימולטור DFS — היכן חוזרים אחורה?

ב־DFS נגיע ל־(2,0), נגלה מבוי סתום, ונחזור כדי לנסות דרך אחרת.

בעיה 2: לא רק האם — אלא איזה מסלול?

שינוי קטן עם משמעות גדולה

נחזיק רשימה path המייצגת את המסלול הפעיל.

path.append((row, col)) — נכנסים לתא.

path.pop() — הכיוון נכשל; מסירים את התא בחזרה לאחור.

אם הגענו ליעד, לא מבצעים pop; הרשימה נשמרת.

דיון: מדוע visited ו־path אינם אותו דבר?

visited כולל גם תאים שנבדקו והסתיימו במבוי סתום. path מכיל רק את שרשרת התאים הנוכחית, ומסיר תאים שלא שייכים למסלול שנמצא.

DFS + Backtracking — שמירת מסלול

def find_path(maze, sr, sc, er, ec):
    if not maze or not maze[0]:
        return []
    rows, cols = len(maze), len(maze[0])
    visited = set()
    path = []

    def dfs(row, col):
        if not (0 <= row < rows and 0 <= col < cols):
            return False
        if maze[row][col] == 1 or (row, col) in visited:
            return False

        visited.add((row, col))
        path.append((row, col))
        if (row, col) == (er, ec):
            return True

        for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            if dfs(row + dr, col + dc):
                return True

        path.pop()  # המבוי הסתום לא שייך למסלול
        return False

    return path if dfs(sr, sc) else []

הפונקציה מחזירה מסלול כלשהו, לא בהכרח את הקצר ביותר. כאשר אין מסלול היא מחזירה רשימה ריקה.

BFS מתאים כשצריך מסלול קצר ביותר במספר צעדים. DFS פשוט ונוח לחיפוש אפשרות כלשהי ולהדגמת רקורסיה וחזרה לאחור. תמיד צריך בדיקות גבול, ביקור קודם, ותכנון ברור של ערך ההחזרה.
