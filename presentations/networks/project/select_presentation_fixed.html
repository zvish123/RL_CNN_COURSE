שקף 2 · ניבוי

מה יקרה ללקוח השני?

client_socket, address = server_socket.accept()
data = client_socket.recv(1024)

הלקוח הראשון מחובר אך אינו שולח שום הודעה. כעת הלקוח השני מנסה להתחבר ולשלוח נתונים.

אם הקריאה ל־recv() חוסמת, התוכנית אינה מגיעה לטיפול בלקוח השני. ייתכן שחיבור TCP חדש ימתין בתור החיבורים — אבל קוד השרת אינו מטפל בו עדיין.

שקף 6 · פענוח

מה בדיוק בודקת השורה?

rlist, wlist, xlist = select.select(
    [server_socket] + open_client_sockets,
    [],
    []
)

server_socket

מוכן לקריאה ⇒ יש חיבור חדש שניתן לקבל באמצעות accept().

open_client_sockets

socket של לקוח מוכן לקריאה ⇒ אפשר לקרוא נתונים או לגלות סיום חיבור.

בשלב הראשון אנו בודקים רק מוכנות לקריאה. אין עדיין בדיקת מוכנות לכתיבה או חריגה. ללא timeout, הקריאה ממתינה עד שיש אירוע.

שקף 9 · שלד קוד

בניית שרת — שלב א'

import socket
import select

server_socket = socket.socket()
server_socket.bind(('127.0.0.1', 8822))
server_socket.listen(5)
open_client_sockets = []

while True:
    rlist, wlist, xlist = select.select(
        [server_socket] + open_client_sockets,
        [], []
    )
    for current_socket in rlist:
        if current_socket is server_socket:
            new_socket, address = server_socket.accept()
            open_client_sockets.append(new_socket)
        else:
            data = current_socket.recv(1024)
            # השלימו טיפול בנתונים או בניתוק

בהדגמה נשתמש ב־localhost ובפורט 8822, בהתאם למצגת המקור.

שקף 10 · למידה מטעויות

איך מזהים ניתוק?

data = current_socket.recv(1024)
if data == b'end':
    open_client_sockets.remove(current_socket)

האם הקוד מזהה את כל הדרכים שבהן לקוח מתנתק?

לא. b'end' הוא סימן מוסכם בפרוטוקול ולא זיהוי ניתוק TCP. כאשר recv() מחזירה b'', פירוש הדבר סוף זרם.

if not data or data == b'end':
    open_client_sockets.remove(current_socket)
    current_socket.close()

במערכת אמיתית יש לטפל גם בשגיאות תקשורת ולזכור ש־TCP הוא זרם של בתים, ולא של הודעות.

שקף 11 · שלב ב'

לא רק לקבל — גם לענות

המצגת המקורית מציעה תור של הודעות ממתינות לשליחה:

messages_to_send = []
# לאחר קבלת הודעה מלקוח:
messages_to_send.append(
    (current_socket, b'Hello, ' + data)
)

בשלב לימודי זה אפשר לחשוב על כל רשומה בתור כ־(socket, bytes).

למה לא לשלוח מיד מתוך ענף הקריאה? כדי להפריד בין קליטת נתונים לבין כתיבתם, ולנסות לשלוח רק כאשר ה־socket מוכן.

שקף 13 · תקלה בקוד

מצא את שלוש הבעיות

for message in messages_to_send:
    client_socket, data = message
    if client_socket in wlist:
        client_socket.send(data)
        messages_to_send.remove(message)
  1. הסרת איברים מהרשימה תוך כדי מעבר עליה יכולה לדלג על הודעות.
  2. send() עשויה לשלוח רק חלק מהבתים.
  3. נדרש טיפול בלקוח שהתנתק ובנתונים שעוד ממתינים עבורו.

יישום עמיד משתמש בדרך כלל ב־buffer נפרד לכל לקוח ומקדם את ההיסט לפי מספר הבתים שנשלחו בפועל.

פתרון משופר: נשמור לכל לקוח מאגר בתים לשליחה. נמחק רק את הבתים שנשלחו בפועל ולא נשנה רשימה בזמן מעבר עליה.

pending = {}  # socket -> bytes waiting to send

# When data arrives and a response is needed:
pending[current_socket] = (
    pending.get(current_socket, b'') + b'Hello, ' + data
)

# Each event-loop iteration:
read_sockets = [server_socket] + open_client_sockets
write_sockets = [s for s in pending if pending[s]]
rlist, wlist, xlist = select.select(
    read_sockets, write_sockets, open_client_sockets
)

# Handle sockets ready for writing:
for client_socket in wlist:
    try:
        sent = client_socket.send(pending[client_socket])
        if sent == 0:
            raise ConnectionError('Connection closed')
        pending[client_socket] = pending[client_socket][sent:]
        if not pending[client_socket]:
            del pending[client_socket]
    except (OSError, ConnectionError):
        pending.pop(client_socket, None)
        if client_socket in open_client_sockets:
            open_client_sockets.remove(client_socket)
        client_socket.close()

זהו קטע לשילוב בלולאת השרת, לא תוכנית מלאה. בכל ניתוק יש להסיר את הלקוח גם ממאגר השליחה. בפרויקט צ'אט אמיתי יש להוסיף מסגור הודעות ל־TCP.

שקף 14 · xlist

מהי xlist — ומתי משתמשים בה?

הרשימה השלישית של select עוסקת במצבי חריגה של socket, לא בכל שגיאה בתוכנית.

rlist, wlist, xlist = select.select(
    [server_socket] + open_client_sockets,
    [],
    open_client_sockets
)

for s in xlist:
    print('Exceptional condition:', s.getpeername())
    # Handle according to the protocol and OS

דוגמה אפשרית

במערכות מסוימות, נתוני TCP דחופים (out-of-band) עשויים לגרום להופעה ב־xlist. ההתנהגות תלויה במערכת ההפעלה ובהגדרות ה־socket.

מה xlist לא מבטיחה?

היא לא מספקת רשימת שגיאות כללית. ניתוק מסודר מזוהה בדרך כלל כאשר recv() מחזירה b'', ושגיאות רגילות מטופלות באמצעות try/except.

שאלת חשיבה: לקוח סגר את החלון והשרת מקבל b'' מ־recv(). האם חייבים לצפות שהלקוח יופיע ב־xlist?

לא. סוף זרם ב־TCP מזוהה דרך הקריאה מה־socket, ואינו מחייב הופעה ב־xlist.

# Typical handling in the rlist branch:
data = current_socket.recv(1024)
if data == b'':
    open_client_sockets.remove(current_socket)
    current_socket.close()

לתרגיל הראשון אפשר להעביר [] כפרמטר השלישי; בשלב זה חשוב בעיקר להבין מדוע אין להסתמך על xlist לאיתור כל ניתוק.

שקף 17 · כרטיס יציאה

האם הבנתם את הרעיון?

1. מה ההבדל בין server_socket לבין socket של לקוח בתוך rlist?

2. מה פירוש החזרה של b'' מ־recv?

3. מדוע wlist אינה רשימת ההודעות הממתינות לשליחה?

  1. הראשון מצביע על חיבור חדש שממתין ל־accept; השני על מוכנות לקריאת נתונים או סוף זרם.
  2. סוף זרם TCP — הצד השני סגר את כיוון השליחה.
  3. wlist מכילה sockets מוכנים לכתיבה; המידע עצמו נשמר בתור או buffer נפרד.

השלב הבא: שרת תשובות ללקוחות → תור הודעות → צ'אט מתקדם (תרגיל 12.6).
