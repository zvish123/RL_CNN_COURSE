Command Pattern

כיצד הופכים פעולה לאובייקט שאפשר לתזמן, לתעד ולבטל?

המשימה

בנו מרכז שליטה ברשת שמנהל פעולות על מחשבים מרוחקים — בלי לקשור את כפתורי הממשק למימוש הפעולות.

השאלה: מה יקרה כשנרצה Queue, History ו־Undo?

3. דרישה חדשה: Queue + History + Undo

⏳ Queue

הפקודה נוצרת כעת אך תבוצע מאוחר יותר.

📜 History

שומרים תיעוד של פקודות שהורצו.

↩ Undo

מחזירים את המצב הקודם כאשר אפשר.

Undo אינו מובטח לכל פעולה: אי אפשר בהכרח לבטל סריקה שכבר בוצעה או הודעה שכבר נשלחה.

את יעד הפעולה (Receiver), הפרמטרים הדרושים, את execute(), ובמידת הצורך גם מידע לשחזור לצורך undo().

4. הרעיון המרכזי של Command

במקום לבצע פעולה ישירות — עוטפים אותה באובייקט פקודה.

Command מפרידה בין מי שמבקש לבצע פעולה לבין מי שיודע לבצע אותה.

5. מי עושה מה?

Client

יוצר את הפקודה ומחבר אותה ל־Receiver.

Command

ממשק משותף לפקודות, למשל execute().

Invoker

מחליט מתי להפעיל פקודה; אינו צריך לדעת איך היא עובדת.

Receiver

האובייקט שמכיל את הפעולה העסקית בפועל.

8. Receiver: המחשב עצמו

class NetworkComputer:
    def __init__(self, name):
        self.name = name
        self.blocked = False

    def block(self):
        self.blocked = True
        print(f"{self.name} blocked")

    def unblock(self):
        self.blocked = False
        print(f"{self.name} unblocked")
Receiver אינו חייב להכיר את Command. הוא מספק פעולות רגילות.

שאלה: אם blocked כבר היה True, מה צריך לקרות לאחר Undo של פקודת חסימה?

המצב צריך להישאר True. Undo צריך לשחזר את המצב הקודם, לא תמיד לקרוא ל־unblock().

9. ConcreteCommand: חסימת מחשב

class BlockComputerCommand(Command):
    def __init__(self, computer):
        self.computer = computer
        self.previous_state = None

    def execute(self):
        self.previous_state = self.computer.blocked
        self.computer.block()

    def undo(self):
        if self.previous_state is None:
            raise RuntimeError("Not executed")
        if self.previous_state:
            self.computer.block()
        else:
            self.computer.unblock()
        self.previous_state = None

מימוש לימודי: כל אובייקט פקודה מבוצע פעם אחת לפני ביטולו. בהרצה חוזרת נדרש מנגנון אחר לניהול היסטוריה.

כדי ש־Undo ישחזר את מצב המחשב לפני הפקודה, גם אם היה חסום כבר קודם.

תרשים מחלקות UML — Command Pattern

המחלקות בדוגמת מרכז השליטה ברשת והקשרים ביניהן.

מיפוי לתבנית

Command — ממשק מופשט; BlockComputerCommand — פקודה קונקרטית; NetworkComputer — Receiver; CommandManager — Invoker; CommandQueue — תור פקודות.

שימו לב

undo() מוגדרת בפקודה הקונקרטית, אך אינה חלק מממשק Command שבמצגת. לכן CommandManager צריך לוודא שהפקודה תומכת בביטול לפני הקריאה.

חץ משולש חלול: ירושה; חץ רציף: הפניה לאובייקט; חץ מקווקו: תלות בממשק.

10. Invoker: מנהל פקודות

class CommandManager:
    def __init__(self):
        self.history = []

    def run(self, command):
        command.execute()
        self.history.append(command)

    def undo_last(self):
        if not self.history:
            return
        command = self.history[-1]
        command.undo()
        self.history.pop()

ה־Invoker אינו יודע מהי חסימה או פתיחת חסימה — הוא רק קורא ל־execute() ול־undo().

הפקודה לא תתווסף להיסטוריה, כי השורה append() לא תתבצע. אבל ייתכן שהפעולה שינתה חלק מהמצב לפני הכישלון; במערכת אמיתית נדרש טיפול מתאים.

13. תור פקודות לביצוע מאוחר

from collections import deque

class CommandQueue:
    def __init__(self):
        self.pending = deque()

    def add(self, command):
        self.pending.append(command)

    def run_next(self):
        if self.pending:
            command = self.pending.popleft()
            command.execute()
Command מאפשרת לשמור פעולה כאובייקט. היא אינה מספקת בעצמה תזמון, Threads, עמידות בתקלות או שמירה למסד נתונים.

אתגר: מה יקרה אם פקודה נכשלת לאחר שהוצאה מהתור?

הפקודה כבר הוצאה. אפשר לתכנן Retry, תור שגיאות או רישום סטטוס — אך צריך להיזהר מביצוע כפול של פעולה שאינה idempotent.

14. טיפול בכישלונות ובבטיחות

הרשאות

יצירת אובייקט Command אינה מהווה אישור לבצע פעולה. יש לבדוק הרשאות במועד הביצוע.

תיעוד

שמרו סטטוס, יעד, תאריך, שגיאה וזהות מבקש הפעולה.

Retry

בדקו אם חזרה על הפעולה עלולה לגרום להשפעה כפולה.

Undo

הגדירו אילו פקודות הפיכות ומה עושים כששחזור נכשל.

במערכת סייבר אמיתית, פעולות ניהול מרחוק מחייבות אימות, הרשאות, תקשורת מאובטחת ולוגים.

17. אתגר יישום: פקודות לכספת קבצים

המערכת הקיימת

vault.upload(name, data)
vault.delete(name)

המשימה

  • ממשו UploadFileCommand
  • ממשו DeleteFileCommand
  • ממשו RenameFileCommand
  • הוסיפו History ו־Undo

לפני כתיבת קוד: מה כל פקודה חייבת לשמור כדי לתמוך בביטול?

Upload צריכה לדעת אם הקובץ היה קיים לפני ההעלאה; Delete צריכה לשמור את התוכן שנמחק; Rename צריכה לשמור את השמות ולבדוק התנגשויות.
class RenameFileCommand(Command):
    def __init__(self, vault, old, new):
        self.vault = vault
        self.old = old
        self.new = new
        self.executed = False

    def execute(self):
        if self.executed:
            raise RuntimeError("Already executed")
        self.vault.rename(self.old, self.new)
        self.executed = True

    def undo(self):
        if not self.executed:
            raise RuntimeError("Not executed")
        self.vault.rename(self.new, self.old)
        self.executed = False

פתרון חלקי ומכוון: יש להוסיף בדיקות התנגשות, הרשאות, תקלות ושינויים חיצוניים בקבצים.
