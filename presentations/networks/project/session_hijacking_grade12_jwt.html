03 · מודל האיום

מה זה Session Hijacking?

תוקף משיג Session Token תקף ומשתמש בו כדי לשלוח בקשות בשם משתמש שכבר התחבר — בלי לדעת את הסיסמה שלו.

📡 דליפה בתקשורת

העברת Token ללא TLS עלולה לחשוף אותו למי שיכול לצפות בתעבורה.

🪲 דליפה בצד לקוח

XSS, תוכנה זדונית או שמירת Token במקום לא מוגן.

📋 דליפה בלוגים

הדפסת Tokens לקונסול, לקובצי לוג או לדוחות שגיאה.
Token תקף הוא כמו מפתח זמני. מי שמחזיק בו עלול להיכנס, גם בלי לדעת את הסיסמה.

05 · הבדל קריטי

Session יחיד ≠ מחשב יחיד

מדיניות Session יחיד

בהתחברות חדשה מאותו חשבון מבטלים את ה־Token הקודם. זו מדיניות שניתן לממש בשרת.

מה היא לא מבטיחה?

אם תוקף העתיק Token קיים, שני מחשבים יכולים להשתמש באותו מזהה. השרת אינו יודע בהכרח שמדובר בשני אנשים.
גם קשירה לכתובת IP אינה זיהוי אמין של מחשב: IP יכול להשתנות או להיות משותף. Session יחיד מפחית חשיפה, אך אינו פותר לבדו גניבת Token.

07 · דרישות מימוש

מה תלמיד י״ב חייב לממש?

1 · Token אקראי

secrets.token_urlsafe(32)

לא מזהה צפוי, לא שם משתמש, ולא מספר רץ.

2 · מצב בשרת

מיפוי Token למשתמש ולזמן תפוגה, ומיפוי משתמש ל־Token הפעיל.

3 · בדיקה בכל פעולה

לאמת Token לפני הורדה, מחיקה, שינוי ושיתוף.

4 · ביטול בהתחברות

Login חדש מבטל את ההפעלה הקודמת.

5 · תפוגה ו־Logout

Token שפג תוקפו או בוטל לא יתקבל.

6 · הצפנה והרשאות

TLS בתעבורה; לאחר אימות Session יש לבדוק הרשאה למשאב.

09 · דוגמת קוד

SessionManager – ליבת הפתרון

import secrets import time class SessionManager: def __init__(self): self.sessions = {} # token -> (user, expiry) self.active_users = {} # user -> token def login(self, user): # call ONLY after password check old = self.active_users.get(user) if old: self.sessions.pop(old, None) token = secrets.token_urlsafe(32) self.sessions[token] = (user, time.time() + 1800) self.active_users[user] = token return token def validate(self, token): session = self.sessions.get(token) if not session: return None user, expiry = session if time.time() >= expiry: self.logout(token) return None if self.active_users.get(user) != token: return None return user def logout(self, token): session = self.sessions.pop(token, None) if session: user = session[0] if self.active_users.get(user) == token: del self.active_users[user]
דוגמה לימודית: בשרת מרובה Threads יש להגן על שינויים משותפים בעזרת threading.Lock או אחסון מתאים. יש לאמת סיסמה לפני login, ולהעביר Tokens רק דרך TLS.

14 · הרחבה: JWT

מהו JWT וכיצד הוא קשור ל־Session?

JWT הוא Token חתום שמכיל Claims (טענות) על המשתמש ועל תוקף ה־Token. הוא יכול לשמש כאמצעי הזדהות בבקשות, אך אינו מחייב שמירת Session בשרת.

Header
.
Payload
.
Signature

Header + Payload

כוללים אלגוריתם ומידע כגון sub, iat, exp, jti.

המידע מקודד, לא מוצפן.

Signature

השרת מאמת שה־Token לא שונה ושנחתם במפתח המתאים. חתימה אינה מונעת העתקה או גניבה.

JWT הוא לרוב Bearer Token: מי שמחזיק בו יכול להשתמש בו עד שפג תוקפו או בוטל בשרת.

18 · מימוש Python

JWT + Session יחיד בשרת

# pip install PyJWT import jwt, secrets from datetime import datetime, timedelta, timezone # SECRET_KEY: מפתח קבוע וסודי המנוהל מחוץ לקוד active_jti = {} # user_id -> jti def issue_token(user_id, secret_key): jti = secrets.token_urlsafe(32) active_jti[str(user_id)] = jti now = datetime.now(timezone.utc) return jwt.encode({ "sub": str(user_id), "jti": jti, "iat": now, "exp": now + timedelta(minutes=30) }, secret_key, algorithm="HS256") def validate_token(token, secret_key): try: claims = jwt.decode( token, secret_key, algorithms=["HS256"], options={"require": ["sub", "jti", "iat", "exp"]} ) user_id = claims["sub"] if active_jti.get(user_id) != claims["jti"]: return None return user_id except jwt.InvalidTokenError: return None
לפני יצירת JWT חייבים לאמת סיסמה. בפרויקט מרובה Threads יש להגן על המאגר מפני גישה מקבילה; לפריסה מתמשכת השתמשו באחסון משותף/מתמיד. Logout מסיר את ה־jti הפעיל.
19 · המלצות לפרויקט הסיום

איזה פתרון לבחור?
