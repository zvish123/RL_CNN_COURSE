Adapter Design Pattern

איך גורמים לשתי מערכות עם ממשקים שונים לעבוד יחד — בלי לשנות את הקוד שלהן?

מערכת ניטור
send_alert()
⇄
Adapter
מתרגם ממשקים
⇄
API חיצוני
publish()
שאלת פתיחה: האם שתי מחלקות חייבות להשתמש באותם שמות מתודות כדי לעבוד יחד?

1. סיפור: התרעה שלא מגיעה ליעדה

בפרויקט ניטור סייבר, השרת מזהה סריקת פורטים ומנסה להתריע. צוות הפיתוח מחליף את שירות ההתרעות בשירות חיצוני — אבל הממשק החדש שונה.

המערכת שלנו

service.send_alert(
    "Port scan detected", "HIGH"
)

השירות החדש

api.publish(
    text="Port scan detected",
    priority=3
)

דיון: מה בדיוק לא תואם? ציינו לפחות שני הבדלים.

חשיפת כיווני חשיבהשם המתודה, שמות הפרמטרים, והייצוג של רמת החומרה.

2. מה הבעיה בקוד?

class SecurityMonitor:
    def __init__(self, alert_service):
        self.alert_service = alert_service

    def detect_threat(self, message):
        self.alert_service.send_alert(message, "HIGH")

כעת מעבירים למחלקה מופע של ExternalAlertAPI שמכיל רק publish().

בחרו תשובה ובדקו.

3. פתרון נאיבי — למה הוא בעייתי?

class SecurityMonitor:
    def detect_threat(self, message, provider):
        if provider == "old":
            self.old_service.send_alert(message, "HIGH")
        elif provider == "new":
            self.new_api.publish(text=message, priority=3)

הקוד עובד, אך ה־Client צריך להכיר כל ספק, את שמות הפעולות שלו ואת אופן מיפוי הנתונים.

שאלת דיון: מה יקרה כשנוסיף ספק שלישי ורביעי? אילו בדיקות עלולות להיפגע?
חשיפת תשובהכל ספק חדש מחייב שינוי ב־SecurityMonitor, מגדיל צימוד ומפזר את תרגום הממשקים בין חלקי המערכת. עם זאת, עבור מקרה חד־פעמי פשוט ייתכן שפונקציית עזר תספיק.

4. הרעיון של Adapter

Adapter עוטף רכיב קיים ומציג כלפי הלקוח את הממשק שהלקוח מצפה לו.

Client
send_alert(msg, severity)
←
Adapter
מיפוי קריאה ונתונים
←
Adaptee
publish(text, priority)
בלי שינוי Client

הקוד הקיים ממשיך לקרוא לממשק המוכר.

בלי שינוי ספרייה חיצונית

ה־Adapter מתרגם את הבקשה לפני העברתה.

אחריות אחת

התאמת הממשקים מרוכזת במקום אחד.

5. מי אחראי למה?

Client

הקוד שמשתמש בשירות, למשל SecurityMonitor.

Target

הממשק המצופה: send_alert(message, severity).

Adaptee

הרכיב הקיים בעל הממשק השונה: ExternalAlertAPI.

Adapter

מחלקה שמממשת את Target וקוראת ל־Adaptee.

בדיקת הבנה: האם Target חייב להיות מחלקת ABC בפייתון?

תשובהלא. אפשר להשתמש ב־ABC, ב־Protocol או ב־Duck Typing. העיקר הוא החוזה שהלקוח מצפה לו.

6. הגדרת Target

אפשר להגדיר חוזה מפורש באמצעות ABC:

from abc import ABC, abstractmethod

class AlertService(ABC):
    @abstractmethod
    def send_alert(self, message: str, severity: str) -> None:
        pass
השלימו: מה תפקיד @abstractmethod?
הצגת הסברמחלקה שיורשת מ־AlertService צריכה לספק מימוש למתודה כדי שנוכל ליצור ממנה מופע קונקרטי. בדוגמה זו החוזה מפורש, אך הוא אינו חובה למימוש Adapter.

7. ה־Adaptee: שירות חיצוני

class ExternalAlertAPI:
    def publish(self, text: str, priority: int) -> None:
        print(f"Priority {priority}: {text}")

איננו משנים את המחלקה הזאת. נניח שהיא חלק מספרייה חיצונית.

שאלת ניבוי: מה הפלט של ExternalAlertAPI().publish("Warning", 2)?
פתרון
Priority 2: Warning

8. מימוש ה־Adapter

class AlertAdapter(AlertService):
    LEVELS = {"LOW": 1, "MEDIUM": 2, "HIGH": 3}

    def __init__(self, external_api: ExternalAlertAPI):
        self.external_api = external_api

    def send_alert(self, message: str, severity: str) -> None:
        if severity not in self.LEVELS:
            raise ValueError("Unknown severity")
        self.external_api.publish(
            text=message,
            priority=self.LEVELS[severity]
        )

מה השתנה? השם והחתימה שהלקוח מכיר נשמרו; הקריאה תורגמה לשירות החיצוני.

מדוע Composition?ה־Adapter מחזיק מופע של השירות החיצוני במקום לרשת ממנו. כך ניתן לעטוף אובייקט קיים ולהחליפו בקלות.

9. Client ללא שינוי

class SecurityMonitor:
    def __init__(self, alert_service: AlertService):
        self.alert_service = alert_service

    def detect_threat(self, message: str):
        self.alert_service.send_alert(message, "HIGH")

api = ExternalAlertAPI()
monitor = SecurityMonitor(AlertAdapter(api))
monitor.detect_threat("Port scan detected")
ניבוי פלט: נסו לכתוב אותו לפני חשיפה.
הצגת הפלט
Priority 3: Port scan detected

אפשר להחליף את השירות כל עוד האובייקט המוזרק תומך בממשק Target.

10. סימולציה חיה — תרגום התרעה

בחרו חומרה ושלחו.

הסימולציה מקומית בלבד ואינה שולחת בקשת רשת.

11. לפני ואחרי Adapter

ללא Adapter

if provider == "a":
    service.send_alert(msg, "HIGH")
elif provider == "b":
    api.publish(text=msg, priority=3)

הלקוח מכיר את הספקים.

עם Adapter

# Client
service.send_alert(msg, "HIGH")

# Adapter
api.publish(text=msg, priority=3)

הלקוח מכיר ממשק אחד.

האם Adapter משפרת ביצועים? לא בהכרח. התועלת העיקרית היא תחזוקתיות, הפרדת אחריות ובידוד תלות.

12. מתי כדאי לבחור Adapter?

בחרו בתבנית כאשר קיים רכיב שימושי, אך הממשק שלו אינו מתאים לחוזה של המערכת.

בחרו תשובה.

13. מתי Adapter מיותרת?

פונקציה חד־פעמית

אם צריך לשנות שדה אחד במקום אחד, פונקציית המרה קטנה עשויה להספיק.

שליטה בשני הממשקים

אם אפשר לתקן חוזה משותף בצורה בטוחה, אין הכרח להוסיף שכבת התאמה.

הבעיה היא בחירת אלגוריתם

ייתכן ש־Strategy מתאימה יותר.

כלל החלטה: אל תוסיפו מחלקות רק כדי להשתמש בשם של תבנית.

15. אתגר יישום — מודיעין סייבר

השרת משתמש ב־reputation_service.check_ip(ip) ומצפה לתוצאה אחידה:

{"ip": "192.0.2.10", "is_suspicious": True}

Service A

{"ip": "192.0.2.10", "risk_score": 85}

Service B

{"address": "192.0.2.10", "threat_level": "high"}

כללי הניסוי: ציון סיכון >= 70 חשוד; רמת high חשודה. אין לבצע פנייה לרשת — השירותים מדומים.

רמז ראשוןצרו שתי מחלקות Adapter, לכל אחת מתודה check_ip(ip), שמחזירה מילון באותו מבנה.
רמז שניהפרידו בין השגת התשובה החיצונית לבין מיפוי השדות. ודאו שה־IP בתשובה תואם לבקשה.

16. קוד התחלתי ופתרון מדורג

class ServiceA:
    def lookup(self, ip):
        return {"ip": ip, "risk_score": 85}

class ServiceB:
    def query(self, ip):
        return {"address": ip, "threat_level": "high"}

# TODO: AAdapter and BAdapter with check_ip(ip)
חשיפת פתרון לדוגמה
class AAdapter:
    def __init__(self, service):
        self.service = service

    def check_ip(self, ip):
        result = self.service.lookup(ip)
        if result.get("ip") != ip or not isinstance(result.get("risk_score"), int):
            raise ValueError("Invalid response")
        return {"ip": ip, "is_suspicious": result["risk_score"] >= 70}

class BAdapter:
    def __init__(self, service):
        self.service = service

    def check_ip(self, ip):
        result = self.service.query(ip)
        if result.get("address") != ip or result.get("threat_level") not in {"low", "medium", "high"}:
            raise ValueError("Invalid response")
        return {"ip": ip, "is_suspicious": result["threat_level"] == "high"}
בדיקות מוצעות
for service in (AAdapter(ServiceA()), BAdapter(ServiceB())):
    assert service.check_ip("192.0.2.10") == {
        "ip": "192.0.2.10", "is_suspicious": True
    }

הרחבה: בדקו ערכי סיכון מחוץ לטווח 0–100, נתונים חסרים ושגיאות רשת מדומות.
