07 · המוטיבציה
למה נבחר Big-Endian ברשתות?
בפרוטוקולי רשת מקובלים, Network Byte Order מוגדר כ־Big-Endian.
  • תאימות: מחשבים שונים מפרשים שדות מרובי־בתים לפי אותו כלל.
  • סטנדרט: לא צריך לנחש את סדר הבתים של הצד השני.
  • פרוטוקול ברור: המפרט קובע כיצד לקודד ולפענח.
דיוק חשוב: אין יתרון קסום ל־Big-Endian בביצועי רשת. היתרון הוא עצם קיום ההסכמה. בפרוטוקולים מסוימים משתמשים דווקא ב־Little-Endian; יש לפעול לפי המפרט.

09 · API בפייתון
קידוד ופענוח של מספר
לקוח: מספר ← בתים
length = 300
header = length.to_bytes(4, "big")
print(header.hex())
# 0000012c
שרת: בתים ← מספר
header = bytes.fromhex("0000012c")
length = int.from_bytes(header, "big")
print(length)
# 300
מה עושה הפרמטר 4? מגדיר את מספר הבתים בייצוג. למה חשוב להשתמש ב־"big" בשני הצדדים?
הפרמטר 4 מקצה בדיוק 4 בתים, ו־"big" מגדיר את סדרם. ללא אותו סדר בשני הצדדים, ייתכן פענוח שגוי.

בפרוטוקול לדוגמה, הלקוח שולח קודם כותרת בת 4 בתים עם אורך ההודעה ב־Big-Endian, ורק אחר כך את תוכן ההודעה.

האורך הוא מספר הבתים ב־payload, לא בהכרח מספר התווים בטקסט.


11 · מלכודת TCP
האם recv(4) מחזיר תמיד 4 בתים?
def recv_exact(sock, size):
    chunks = bytearray()
    while len(chunks) < size:
        part = sock.recv(size - len(chunks))
        if not part:
            raise ConnectionError("Connection closed")
        chunks.extend(part)
    return bytes(chunks)
קודם קוראים בדיוק 4 בתים לכותרת; לאחר פענוח האורך, קוראים בדיוק את מספר בתי ההודעה (ובודקים שהאורך סביר).


12 · קוד שרת
כך מקבלים הודעה בצורה מסודרת
# recv_exact is defined on the previous slide
header = recv_exact(sock, 4)
length = int.from_bytes(header, "big")

MAX_MESSAGE_SIZE = 1024 * 1024
if length > MAX_MESSAGE_SIZE:
    raise ValueError("Message too large")

payload = recv_exact(sock, length)
message = payload.decode("utf-8")
print(message)
שתי החלטות נפרדות: סדר הבתים של שדה האורך (big) והקידוד של הטקסט (utf-8).
לקוח לא מהימן יכול לשלוח כותרת שמצהירה על אורך עצום. בדיקת גבול מצמצמת שימוש לא מבוקר במשאבים, אך אינה תחליף ל־timeouts והגנות נוספות.


13 · אתגר קבוצתי
תקנו את באג הפרוטוקול
הלקוח שולח אורך בשני בתים ב־Big-Endian, אבל השרת מפענח כך:
# CLIENT
header = len(payload).to_bytes(2, "big")
sock.sendall(header + payload)

# SERVER (BUG!)
header = recv_exact(sock, 2)
length = int.from_bytes(header, "little")
משימה: זהו את הבאג, הציעו תיקון, וכתבו בדיקה שבה התקלה תתגלה.
תיקון: int.from_bytes(header, "big").
# TEST: length 256
header = (256).to_bytes(2, "big")
assert int.from_bytes(header, "big") == 256
assert int.from_bytes(header, "little") == 1
