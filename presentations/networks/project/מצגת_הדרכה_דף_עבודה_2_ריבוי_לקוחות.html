מחלקה שיורשת מ־Thread

חלופה ל־target: מגדירים מחלקה עם התנהגות ב־run(). דוגמה כללית של שעון עצר.

import threading

class Countdown(threading.Thread):
    def __init__(self, seconds):
        super().__init__()
        self.seconds = seconds

    def run(self):
        for number in range(self.seconds, 0, -1):
            print(number)

timer = Countdown(3)
timer.start()

super().__init__() מאתחל את החלק של Thread במחלקה היורשת. אין ליצור Thread נוסף סביב אובייקט שהוא כבר Thread.

threading.Lock וקטע קריטי

Lock מתיר ל־Thread אחד בלבד להיות בקטע מוגן בו־זמנית.

import threading

counter = 0
mutex = threading.Lock()

def record_sale():
    global counter
    with mutex:
        counter += 1
with דואג לשחרור המנעולאותו Lock לכל הגישות לאותו מידעקטע מוגן קצר ככל האפשר

דוגמת קופה כללית בלבד. ההגנה מתאימה למידע משותף גם אם מבחני ריצה פשוטים אינם חושפים תקלה.

Lock אינו פתרון לכל בעיה

מתי מתאים Lock?

  • עדכון רשימה משותפת
  • קריאת מצב שדורשת תמונת מצב עקבית
  • רישום משותף שבו נדרשת אחידות

מה לא עושים?

  • לא מחזיקים Lock בזמן recv()
  • לא מחכים ל־join() תוך החזקת אותו Lock
  • לא נועלים משאבים בלתי קשורים סתם
מהו הסיכון כש־Thread א׳ מחזיק מנעול ומחכה ל־Thread ב׳, שממתין לאותו מנעול?
Deadlock — שתי זרימות ביצוע ממתינות זו לזו והמערכת נתקעת.

close() לעומת shutdown()

sock.close()

משחררת את ה־socket שבידי התוכנית. לא כדאי להניח שבכל מערכת היא תעיר מיד Thread אחר החסום ב־recv().

sock.shutdown(socket.SHUT_RDWR)

מבקשת להפסיק פעולות שליחה וקבלה בחיבור. עשויה לסייע להוציא קריאת רשת חסומה כדי לאפשר סיום.

כאשר החיבור כבר סגור, shutdown() עשויה להעלות OSError. מטפלים בכך בצורה מכוונת ולא מסתירים כל שגיאה באופן גורף.
