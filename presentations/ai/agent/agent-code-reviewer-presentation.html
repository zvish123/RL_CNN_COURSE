01 · הוקהסוכן שאישר את הדליפה

חברת תשלומים קטנה. שני מפתחים, ארבעים PR בשבוע, אפס זמן ל-code review אנושי. הם מחברים סוכן AI שסוקר כל שינוי קוד לפני מיזוג. הסוכן עובד יפה: כל שבוע הוא מחזיר שישה עד עשרה ממצאים, מנוסחים בביטחון, עם המלצות תיקון.

אחרי חודשיים דולף מפתח API. הוא ישב קשיח בתוך קובץ שהסוכן סרק — ואישר.

השאלה של השיעור: איך מישהו היה יכול לדעת מראש שהסוכן הזה לא מספיק טוב?

אף אחד לא הריץ אותו על קוד שבו ידעו מראש איפה הבאגים. סוכן שאף פעם לא נבחן מול אמת מוצא הוא לא כלי — הוא תחושה. היום אתם בונים את שניהם: את הסוכן, ואת המבחן שלו.

02 · מטרותבסוף השיעור תדעו

  • להסביר מאילו ארבעה רכיבים בנוי סוכן ב-Claude Code, ואיזה קובץ אחראי על כל אחד.
  • לזהות ולנמק לפחות חמש פגיעויות אבטחה בקוד Python נתון, עם מספרי שורות.
  • לכתוב קובץ הגדרת תת-סוכן תקין, ולהסביר למה הגבלת הכלים שלו היא החלטת אבטחה ולא החלטה טכנית.
  • למדוד סוכן מול אמת מוצא: לחשב recall ו-precision, ולהסיק מהמספרים מה לשנות בפרומפט.

03 · הגדרהמה זה בעצם "סוכן"

agent = model + system prompt + tools + permissions
  • model — המנוע. אתם לא בונים אותו, אתם בוחרים אותו.
  • system prompt — מי הסוכן, מה הוא בודק, באיזה פורמט הוא מדווח.
  • tools — מה מותר לו לגעת בו: לקרוא קבצים, לחפש בהם, לכתוב, להריץ פקודות.
  • permissions — מה קורה כשהוא מבקש לעשות משהו מסוכן.

שימו לב: אף אחד מארבעת הרכיבים אינו קוד. כולם טקסט. לכן אפשר לבנות את הסוכן של היום בלי לכתוב שורת פייתון אחת — וגם לכן קל להתבלבל ולחשוב שבנינו משהו חזק ממה שבנינו.

06 · עיקרוןלמה קריאה בלבד

tools: Read, Grep, Glob
אין Write. אין Edit. אין Bash.

זו לא הגבלה טכנית — זו הרשאת מינימום (least privilege), בדיוק כמו משתמש במערכת הפעלה. סוקר לא צריך ידיים.

  • הוא ישנה את הקוד שאתם מנסים להעריך — ואז אין לכם מה להשוות.
  • הוא "יתקן" ממצאי שווא ויכניס באגים אמיתיים.
  • נתתם הרשאת כתיבה לקבצים שלכם לתהליך שמקבל את ההוראות שלו מטקסט שהוא קרא.

הנקודה השלישית תחזור בסוף השיעור.

■ תחנת עצירה 1 — 7 דקות, לבד

לפני שמערבים AI: סרקו את הקוד בעצמכם וסמנו בדף העבודה כל דבר שנראה לכם פגיעות, עם מספר שורה. אל תפתחו את Claude. עדיין.

07 · מדידהאיך יודעים שסוכן טוב

בקובץ שראיתם יש 8 פגיעויות מתוכננות. כל ממצא של הסוכן נופל לאחת משלוש קטגוריות:

TPממצא נכון — פגיעות אמיתית שהוא תפס
FPהתרעת שווא — הוא דיווח על משהו שאינו פגיעות
FNפספוס — פגיעות אמיתית שהוא לא הזכיר
recall = TP / (TP + FN)   ·   precision = TP / (TP + FP)
סוכן דיווח 10 ממצאים. 5 מהם נכונים. מה ה-precision שלו?

התשובה הראשונה היא ה-recall. שתי המידות עונות על שאלות שונות: כמה הוא מצא, מול כמה אפשר לסמוך עליו.

■ תחנת עצירה 2 — 30 דקות

כתבו את הסוכן שלכם בדף העבודה: description, צ'קליסט ממוספר, ופורמט פלט קבוע. אני אריץ ארבעה מהם מול הכיתה.

מה מעלה ניקוד

  • צ'קליסט ממוספר במקום "בדוק אבטחה"
  • דרישה למספר שורה בכל ממצא
  • סעיף נפרד ל"לא בטוח" — מוריד התרעות שווא

מה מוריד ניקוד

  • "תהיה יסודי מאוד" — לא אומר כלום
  • פרומפט של 400 מילה שאף אחד לא קרא
  • לבקש גם לתקן — שינינו את מה שמדדנו

08 · טורנירכללי המשחק

  • כל סוכן רץ על אותו קובץ, עם אותה בקשה: "סרוק את login_service.py".
  • ממצא נספר רק אם יש בו מספר שורה ותיאור שמזהה את הבעיה נכון.
  • ניסוח שונה לאותה פגיעות — נחשב פעם אחת.
  • הניקוד: TP ×2  ·  FP ×(−1)  ·  פספוס 0.

לפני שמתלהבים: אריץ את הסוכן המנצח פעמיים על אותו קובץ. אם התוצאה תשתנה — וזה יקרה — זו לא תקלה. זה המאפיין המרכזי של הכלי שאתם בונים, ויש לו משמעות ישירה על השאלה מתי מותר לסמוך עליו.

09 · AIחשוב · כתוב · בדוק · שאל

חשובסקירה ידנית לפני כל שימוש ב-AI. אחרת אתם רק מאשרים את מה שהוא אמר.
כתובהפרומפט הוא שלכם. מותר להיעזר, אסור להדביק משהו שאתם לא יכולים להסביר שורה-שורה.
בדוקכל ממצא מאומת מול הקוד. סוכן מנסח ביטחון גם כשהוא טועה.
שאלממצא שלא הבנתם — שאלה, לא העתקה.

הקוד שהסוכן סורק הוא קלט לא אמין. הערה בתוך קובץ יכולה להכיל טקסט שמנסה להורות לסוכן מה לעשות — prompt injection. Claude Code מסמן פלט של תת-סוכן שמחקה הוראות מערכת, אבל זו הקשחה, לא חסינות. ההגנה האמיתית היא זו שכבר בניתם: סוכן בלי Write ובלי Bash לא יכול לבצע כמעט שום הוראה זדונית שיקרא.

10 · סיכוםשאלות הבנה

1. מה ההבדל בין description לבין גוף הקובץ?

description קובע מתי הסוכן נקרא — הוא נקרא לפני שהסוכן רץ. הגוף קובע איך הוא עובד — הוא נטען רק אחרי שהוחלט להפעיל אותו.

2. תלמיד טוען: "הסוכן שלי החזיר 14 ממצאים, שלך 6 — שלי טוב יותר". הפריכו.

מספר ממצאים אינו מדד. 14 ממצאים עם 5 נכונים = precision של 36%, כלומר שני שלישים מזמן הסוקר האנושי מבוזבזים. סוכן עם 6 ממצאים ו-6 נכונים שווה יותר. רק TP, FP ו-FN ביחד אומרים משהו.

3. למה השוואת טוקן עם == היא פגיעות, ומה החלופה?

ההשוואה נעצרת בתו הראשון שנכשל, ולכן זמן התגובה מסגיר כמה תווים ראשונים נכונים — תוקף יכול לשחזר את הטוקן תו אחר תו. החלופה: השוואה בזמן קבוע, למשל hmac.compare_digest.

4. רפלקציה — לענות בדף העבודה
  • איזה ממצא אתם מצאתם והסוכן פספס? למה דווקא הוא היה קשה למכונה?
  • מה שיניתם בפרומפט בין גרסה 1 לגרסה 2, ומה קרה בפועל — לעומת מה שציפיתם?
  • באיזה תנאי הייתם מסכימים שסוכן כזה יאשר קוד בלי עין אנושית? אם התשובה "בשום תנאי" — מה היה צריך להשתנות?

לוגיסטיקה של הטורניר

  • הכינו מראש תיקיית פרויקט עם login_service.py ותיקייה .claude/agents/ קיימת — אם התיקייה נוצרת תוך כדי סשן, Claude Code לא מזהה אותה עד הפעלה מחדש. זו התקלה שתתפוס אתכם בכיתה.
  • הדביקו כל סוכן לקובץ .claude/agents/secure-reviewer.md (דורסים בכל סבב), ובקשו: "השתמש בסוכן secure-reviewer כדי לסרוק את login_service.py".
  • ארבעה סוכנים × כ-2 דק' = 8–10 דק' הרצה. השאירו זמן לספירת ניקוד על הלוח.
  • הריצו את המנצח פעמיים. ההבדל בין ההרצות הוא השיעור האמיתי.

טעויות נפוצות של תלמידים

  • מנסחים description כתיאור פנימי ("סוכן שאני בניתי") במקום כתנאי הפעלה.
  • מוסיפים Write ל-tools "ליתר ביטחון" — הזדמנות לדיון, לא לתיקון מיידי.
  • סופרים כל ניסוח כממצא נפרד ומנפחים TP. אכפו את כלל מספר השורה.
  • מסיקים מהרצה אחת. דרשו השערה לפני גרסה 2, ובדיקה אחריה.

הקלה: תנו את הצ'קליסט מוכן ובקשו רק description ופורמט פלט.
הקשחה: בקשו מזוג אחד לשתול פגיעות תשיעית בקוד ולראות אם סוכני האחרים תופסים אותה.
