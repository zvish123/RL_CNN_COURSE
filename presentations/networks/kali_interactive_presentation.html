מהו VirtualBox? 🖥️

VirtualBox היא תוכנת וירטואליזציה בקוד פתוח שמאפשרת להריץ מספר מערכות הפעלה על אותו מחשב בו-זמנית.

למה זה נקרא "וירטואלי"?

כי אנחנו יוצרים מחשב "מדומה" (virtual) בתוך המחשב האמיתי שלנו. המחשב הווירטואלי חושב שהוא מחשב אמיתי עם חומרה משלו, אבל בפועל הוא פשוט תוכנה שרצה על המחשב האמיתי.

יתרונות שימוש ב-VirtualBox:

  • בטיחות: ניתן לבדוק תוכנות מסוכנות בסביבה מבודדת
  • גמישות: אפשר להריץ Windows, Linux, ו-macOS בו זמנית
  • למידה: אפשר ללמוד מערכות הפעלה חדשות בלי לסכן את המחשב הראשי
  • בדיקות: מעולה לפיתוח תוכנה ובדיקת תאימות
דוגמה: מבנה המערכת

הגדרות רשת קריטיות 🌐

כדי להסניף תעבורה, צריך להגדיר נכון את הרשת:

1

Bridged Adapter

שנו את "Attached to" ל-Bridged Adapter

משמעות: המכונה הווירטואלית תתחבר ישירות לרשת הפיזית ותקבל כתובת IP עצמאית, כאילו היא מחשב נפרד ברשת.

2

Promiscuous Mode

שנו ל-Allow All

משמעות: כרטיס הרשת יקבל את כל חבילות הנתונים ברשת, לא רק אלו שמיועדות אליו.

מהו Promiscuous Mode? 👂

דמיינו שאתם בחדר מלא אנשים שמדברים:

  • מצב רגיל: אתם שומעים רק שיחות שמופנות אליכם ישירות
  • Promiscuous Mode: אתם שומעים את כל השיחות בחדר, גם אם הן לא מופנות אליכם

ברשת, זה אומר שכרטיס הרשת יקלוט את כל החבילות שעוברות, לא רק אלו שמיועדות למחשב שלכם.

שאלת הבנה - הגדרות רשת 🤔

מדוע Promiscuous Mode חיוני להסנפת תעבורה?

הסבר מפורט:

בדרך כלל, כרטיס רשת עובד כמו שומר בכניסה למועדון - הוא מאפשר כניסה רק למי ששמו על הרשימה (חבילות שמיועדות לכתובת ה-MAC שלו). כל שאר החבילות? הן נזרקות לפח.

כשPromiscuous Mode מופעל, השומר הופך ל"כתב עיתונאי" - הוא מקליט את כולם שנכנסים, לא רק את מי ששמו על הרשימה. ככה אנחנו יכולים לראות את כל התעבורה ברשת, גם אם היא לא מיועדת אלינו.

💡 זכרו: בלי Promiscuous Mode, נראה רק את התעבורה שלנו. עם Promiscuous Mode, נראה את התעבורה של כולם ברשת!

Port Scanning - סריקת פורטים 🔍

Port Scanning הוא תהליך של בדיקה אילו פורטים פתוחים במחשב או שרת מסוים.

מהו פורט?

פורט הוא כמו דלת בבניין - כל שירות ברשת "מקשיב" על פורט מסוים. לדוגמה:

  • פורט 80 - HTTP (גלישה רגילה)
  • פורט 443 - HTTPS (גלישה מוצפנת)
  • פורט 22 - SSH (חיבור מרחוק)
  • פורט 21 - FTP (העברת קבצים)

מהו Nmap?

Nmap (Network Mapper) הוא כלי קוד פתוח למיפוי רשתות, גילוי מחשבים פעילים, בדיקת מצבי פורטים וזיהוי שירותים. הוא שולח בקשות בדיקה ומנתח את התשובות או את היעדרן. הפקודה לבדיקת גרסה אינה שולחת בקשות לרשת.

התחביר הכללי: nmap [options] target — שם הכלי, אפשרויות הבדיקה וכתובת היעד. פורט פתוח אינו כשלעצמו הוכחה לחולשת אבטחה.

שאלת יישום - Port Scanning 🤔

אתם רוצים לסרוק את כל הפורטים (1-65535) במחשב 192.168.1.50. איזו פקודה נכונה?

הסבר הפקודה:

  • nmap - הכלי לסריקת פורטים
  • -p- - הדגל שאומר "סרוק את כל הפורטים" (1-65535)
  • 192.168.1.50 - כתובת ה-IP של היעד

חלופות:

  • nmap 192.168.1.50 - יסרוק רק את 1000 הפורטים הנפוצים
  • nmap -p 1-1000 192.168.1.50 - יסרוק פורטים 1 עד 1000
  • nmap -p 80,443 192.168.1.50 - יסרוק רק פורטים 80 ו-443

💡 טיפ: סריקת כל הפורטים יכולה לקחת זמן רב. התחילו עם סריקה בסיסית ורק אם צריך - סרקו את כולם.

ARP Spoofing - התחזות ברשת 🎭

ARP Spoofing היא מתקפה שבה אנחנו שולחים הודעות ARP מזויפות כדי לגרום למחשבים לשלוח את התעבורה שלהם דרכנו.

מהו פרוטוקול ARP?

ARP = Address Resolution Protocol

זה הפרוטוקול שעוזר למחשבים למצוא אחד את השני ברשת מקומית.

איך זה עובד?

מחשב A רוצה לדבר עם מחשב B. הוא יודע את כתובת ה-IP של B, אבל לא את כתובת ה-MAC (הכתובת הפיזית).

אז מחשב A שואל לכולם ברשת: "מי יש לו את ה-IP 192.168.1.10?"

מחשב B עונה: "זה אני! כתובת ה-MAC שלי היא AA:BB:CC:DD:EE:FF"

מה קורה ב-ARP Spoofing?

במקום שמחשב B יענה, אנחנו עונים במקומו:

"זה אני! כתובת ה-MAC שלי היא XX:YY:ZZ..." (השקר שלנו)

עכשיו מחשב A חושב שאנחנו מחשב B, ושולח אלינו את כל התעבורה המיועדת ל-B!

הכלי: arpspoof

# התקנה
$ sudo apt-get install dsniff
# רימוי מכשיר היעד
$ sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
התקנת dsniff — הצג פלט והסבר
$ sudo apt-get install dsniff

פלט מדומה ומקוצר; אם החבילה כבר מותקנת, תופיע הודעה מתאימה.

sudo — הרשאות מנהל; apt-get — מנהל חבילות; install — התקנה; dsniff — חבילת כלי רשת הכוללת arpspoof.

Reading package lists — קריאת רשימות חבילות; Building dependency tree — בדיקת תלויות; Setting up — הגדרת החבילה.

arpspoof — הצג הסבר ופלט שגיאה

הכלי שולח הודעות ARP מזויפות. שימוש בו עלול לשבש תקשורת ולשנות את מיפוי כתובות IP לכתובות MAC. יש ללמוד את התופעה בסימולציה או במעבדה מבודדת ומורשית.

arpspoof: couldn't arp for host 192.168.10.233

זהו הפלט שסופק בתרגול: הכלי לא הצליח לגלות את כתובת ה-MAC של היעד. לפי הנתונים הקודמים זו כתובת המחשב המקומי עצמו. אין להסיק מכך שהיעד כבוי.

במקום להפעיל התחזות ברשת פעילה, ניתן לבדוק את מיפוי השכנים באופן מקומי:

$ ip neigh show dev eth0
192.168.10.1 lladdr 00:11:22:33:44:55 REACHABLE

פלט מדומה: כתובת IP של שכן, lladdr — כתובת MAC, REACHABLE — השכן אומת לאחרונה כנגיש. שינוי בלתי צפוי במיפוי עשוי להצדיק בדיקה, אך אינו מוכיח מתקפה.

MITM - Man in the Middle 🕴️

MITM היא מתקפה שבה אנחנו יושבים באמצע בין שני צדדים ויכולים לראות ולשנות את התעבורה ביניהם.

איך זה עובד?

מחשב היעד ➜ האקר (אנחנו) ➜ הנתב ➜ אינטרנט
↑ תעבורה שהוסטה עשויה לעבור דרך המתווך; TLS מגביל חשיפת תוכן ↑

שלבי ביצוע MITM מלא:

1

הפעלת IP Forwarding

sudo sysctl -w net.ipv4.ip_forward=1
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

net.ipv4.ip_forward = 1

sudo — הרשאות מנהל; sysctl — ממשק להגדרות הליבה; ‎-w — כתיבת ערך; net.ipv4.ip_forward — הגדרת העברת IPv4; 1 — מופעל. הפלט מציין שהערך נכתב, ולא מוכיח שחבילות אכן מועברות. הגדרה זו משמשת גם נתבים לגיטימיים.

למה? כדי שהתעבורה תעבור דרכנו ולא תיעצר אצלנו

2

איתור היעדים

ip route | grep default # מציאת הנתב
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

default via 192.168.10.1 dev eth0 proto dhcp src 192.168.10.233 metric 100

ip route מציג נתיבים; | מעביר את הפלט ל־grep; default מסנן את נתיב ברירת המחדל. via הוא שער ברירת המחדל, dev הממשק, proto מקור הנתיב, src כתובת המקור המועדפת ו־metric העדיפות. זהו הפלט שסופק קודם; כתובות המצגת המקורית שונות.

nmap -sn 192.168.1.0/24 # סריקת הרשת
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

Nmap scan report for 192.168.1.20
Host is up (0.0012s latency).
Nmap done: 256 IP addresses (1 host up) scanned in 2.10 seconds

nmap הוא כלי מיפוי; ‎-sn מבצע גילוי יעדים ללא סריקת פורטים; /24 מגדיר טווח של 256 כתובות. Host is up מציין יעד שהגיב; latency הוא זמן תגובה מוערך. הדוגמה מדומה ואינה מוכיחה שכל יתר המחשבים כבויים.

3

רימוי דו-כיווני

טרמינל 1: רמה את היעד

sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

arpspoof: couldn't arp for host 192.168.10.233

arpspoof שולח הודעות ARP מזויפות; ‎-i מציין ממשק ו־‎-t מציין יעד. הודעת השגיאה שסופקה קודם מעידה שלא התקבלה כתובת MAC מתאימה. זו אינה תוצאת הרצה של הפקודה המוצגת בשקף. סימן הגנתי אפשרי: שינוי בלתי צפוי במיפוי IP ל־MAC.

טרמינל 2: רמה את הנתב

sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.10
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

דוגמת תצפית הגנתית: שינוי בלתי צפוי בכתובת MAC של שכן

השלב מתאר התחזות בכיוון ההפוך. ARP מקשר בין כתובת IPv4 לכתובת MAC ברשת המקומית. שינוי במיפוי אינו הוכחה למתקפה: גם החלפת ציוד עשויה לגרום לו. מוצגת תצפית תאורטית ולא פלט הצלחה של התחזות.

4

הסנפת התעבורה

sudo wireshark
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

חלון Wireshark נפתח (אם מותקנת סביבת GUI מתאימה)

sudo מעניק הרשאות מנהל; wireshark פותח מנתח חבילות גרפי. אין פלט טקסט קבוע. אפשר לבחון חבילות מורשות במעבדה או קובץ PCAP קיים. אין צורך בדרך כלל להפעיל את כל הממשק הגרפי כמנהל.

או

sudo tcpdump -i eth0 -w mitm_capture.pcap
הצג / הסתר פלט והסבר

פלט או תצפית להמחשה

tcpdump: listening on eth0, link-type EN10MB (Ethernet)
12 packets captured

tcpdump הוא מנתח חבילות; ‎-i בוחר ממשק; ‎-w כותב לקובץ PCAP במקום להציג פירוט חבילות. listening מציין התחלת לכידה; packets captured הוא מספר החבילות שנלכדו בסיום. פלט מדומה ללכידת תעבורה עצמית מורשית בלבד.

שאלת הבנה - MITM 🤔

מדוע צריך להפעיל IP Forwarding במתקפת MITM?

הסבר מפורט:

כאשר מבצעים ARP Spoofing, התעבורה של מכשיר היעד מגיעה למחשב שלנו. ברירת המחדל של מערכת ההפעלה היא לזרוק חבילות שלא מיועדות אליה.

בלי IP Forwarding:

  • החבילות מגיעות אלינו ➜ נזרקות לפח ❌
  • מכשיר היעד מאבד חיבור לאינטרנט
  • המשתמש מבין שמשהו לא בסדר!

עם IP Forwarding:

  • החבילות מגיעות אלינו ➜ נשמרות ➜ מועברות הלאה ✅
  • מכשיר היעד ממשיך לעבוד רגיל
  • המשתמש לא מרגיש שום דבר!

זכרו: IP Forwarding הופך אותנו ל"נתב" שדרכו עוברת התעבורה. זה קריטי לביצוע MITM נסתר!

DNS Spoofing - הפנייה מחדש 🔀

DNS Spoofing היא מתקפה שבה אנחנו מחזירים תשובות DNS מזויפות, ומפנים משתמשים לאתרים לא נכונים.

מהו DNS?

DNS = Domain Name System

זה כמו ספר טלפונים של האינטרנט:

  • אתם מקלידים: www.google.com
  • DNS מחזיר: 142.250.185.46 (כתובת ה-IP)
  • הדפדפן מתחבר לכתובת ה-IP

מה קורה ב-DNS Spoofing?

אנחנו יירטים את השאילתה ומחזירים תשובה מזויפת:

  • משתמש שואל: "מה ה-IP של www.bank.com?"
  • אנחנו עונים: "זה 10.0.0.123" (אתר מזויף שלנו!)
  • המשתמש נכנס לאתר המזויף שלנו במקום לבנק האמיתי 😱

שלבי ביצוע:

1

יצירת קובץ Hosts מזויף

# תוכן הקובץ fake_hosts.txt
10.0.0.123 www.example.com
10.0.0.124 mail.example.com
2

הפעלת dnsspoof

sudo dnsspoof -f fake_hosts.txt
3

שילוב עם MITM

DNS Spoofing יעיל במיוחד כשמשולב עם ARP Spoofing - כל התעבורה עוברת דרכנו וגם שאילתות ה-DNS!

שאלת יישום - DNS Spoofing 🤔

אתם רוצים שכל הגישות ל-facebook.com יופנו ל-10.0.0.50. מה צריך לכתוב בקובץ fake_hosts.txt?

מבנה קובץ Hosts:

כל שורה בקובץ בנויה כך:

[כתובת IP] [שם דומיין]
דוגמאות:
192.168.1.100 www.mysite.com
10.0.0.50 facebook.com
10.0.0.50 www.facebook.com

חשוב: הכתובת IP תמיד באה לפני שם הדומיין!

שימושים "לגיטימיים" של DNS Spoofing:

  • חסימת אתרים מסוכנים ברשת ארגונית
  • הפניה לשרת פיתוח במקום לשרת הייצור
  • בדיקת התנהגות אפליקציות בתרחישי כשל

תרחיש התקפה מלא 🎯

בואו נשלב את כל מה שלמדנו למתקפה מלאה:

המטרה:

להסניף את התעבורה של מחשב 192.168.1.50 ולהפנות אותו לאתר מזויף

1

הכנה

sudo sysctl -w net.ipv4.ip_forward=1
הצג / הסתר פלט והסבר

פלט לדוגמה של הגדרת נתב

net.ipv4.ip_forward = 1

sudo — הרשאות מנהל; sysctl — כלי לקריאת הגדרות הליבה ולשינוין; ‎-w — כתיבה; net.ipv4.ip_forward — העברת חבילות IPv4; 1 — מופעל. הפלט מעיד על שינוי ההגדרה, לא על העברה בפועל.

ip route | grep default # למצוא הנתב
הצג / הסתר פלט והסבר

הפלט שסופק קודם (רשת שונה מהדוגמה בשקף)

default via 192.168.10.1 dev eth0 proto dhcp src 192.168.10.233 metric 100

ip route — טבלת ניתוב; | — העברת הפלט; grep default — סינון נתיב ברירת המחדל. via — שער; dev — ממשק; proto — מקור הנתיב; src — כתובת מקור מועדפת; metric — עדיפות.

2

הגדרת DNS מזויף

$ echo "10.0.0.123 www.bank.com" > fake_hosts.txt
הצג / הסתר פלט והסבר

התנהגות כללית של הפניית פלט

אין פלט למסוף בעת כתיבה מוצלחת לקובץ.

echo מדפיס טקסט; הסימן > מפנה פלט לקובץ ומחליף את תוכנו הקודם. בתרחיש המקורי הקובץ מתאר מיפוי שם מתחם לכתובת IP חלופית. יצירת קובץ כשלעצמה אינה משנה DNS.

3

הפעלת המתקפות (4 טרמינלים!)

# טרמינל 1: ARP Spoofing ליעד
$ sudo arpspoof -i eth0 -t 192.168.1.50 192.168.1.1
הצג / הסתר פלט והסבר

שגיאה שסופקה קודם, לא פלט של הפקודה בשקף

arpspoof: couldn't arp for host 192.168.10.233

arpspoof הוא כלי לשליחת הודעות ARP מזויפות. הפעולה המתוארת מכוונת לשינוי מיפוי IP–MAC אצל מחשב אחר. ניתן לזהות חשד באמצעות השוואת מיפויי שכנים לערכי בסיס מוכרים.

# טרמינל 2: ARP Spoofing לנתב
$ sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.50
הצג / הסתר פלט והסבר

תצפית הגנתית, לא פלט הצלחה

תצפית מדומה: מיפוי IP–MAC השתנה באופן בלתי צפוי.

השלב מתאר ניסיון לשינוי מיפוי ARP בצד השני של התקשורת. שינוי כתובת MAC של שכן עשוי להעיד על התחזות, אך גם על החלפת ציוד.

# טרמינל 3: DNS Spoofing
$ sudo dnsspoof -f fake_hosts.txt
הצג / הסתר פלט והסבר

תצפית הגנתית, לא פלט הצלחה

תצפית מדומה: תשובת DNS שונה מערך הבסיס המאומת.

dnsspoof הוא כלי להפקת תשובות DNS מזויפות. בתרחיש מתואר ניסיון להחזיר כתובת שאינה הכתובת הצפויה של שם מתחם. תשובה חריגה אינה הוכחה בפני עצמה למתקפה. אימות TLS תקין עשוי למנוע התחזות לאתר.

# טרמינל 4: הסנפת תעבורה
$ sudo wireshark
הצג / הסתר פלט והסבר

תוצאה צפויה, אין פלט מסוף קבוע

חלון Wireshark נפתח אם התוכנה וסביבת התצוגה זמינות.

sudo — הרשאות מנהל; wireshark — מנתח חבילות גרפי. בדרך כלל אין צורך להפעיל את הממשק הגרפי כולו כמנהל. ניתן לפתוח קובץ PCAP לימודי ולבחון בו ARP, DNS ו-TLS. הצפנת TLS מגינה על תוכן התקשורת.

⚠️ זכרו: זהו תרחיש לימודי בלבד! ביצוע מתקפות כאלו ברשתות אמיתיות ללא הרשאה הוא פשע חמור.

איך מגנים מפני המתקפות האלה? 🛡️

הגנה מפני ARP Spoofing:

  • Static ARP Entries: הגדרת קבועה של כתובות MAC
  • ARP Inspection: סוויצ'ים חכמים שבודקים הודעות ARP
  • Network Monitoring: כלים שמזהים שינויים חשודים

הגנה מפני DNS Spoofing:

  • DNSSEC: חתימות דיגיטליות על תשובות DNS
  • HTTPS Everywhere: שימוש בהצפנה תמיד
  • Certificate Validation: בדיקת תעודות SSL

הגנה כללית מפני הסנפת תעבורה:

  • VPN: הצפנת כל התעבורה
  • HTTPS: שימוש באתרים מוצפנים בלבד
  • Encrypted DNS: DNS over HTTPS (DoH)
  • Network Segmentation: הפרדה בין רשתות

המלצות למשתמשים:

  • אל תתחברו לרשתות WiFi ציבוריות ללא VPN
  • בדקו תמיד שיש מנעול בשורת הכתובת (HTTPS)
  • היזהרו מאזהרות תעודות SSL
  • השתמשו באימות דו-שלבי (2FA)

סיכום המסע 🎓

מה למדנו היום:

  • ✅ VirtualBox: סביבה וירטואלית בטוחה ללמידה
