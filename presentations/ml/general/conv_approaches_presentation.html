הבעיה: איך לחבר שני "רואים" של אותו לוח?

יש לנו קלט אחד (לוח משחק) ושתי קונבולוציות בגדלי קרנל שונים. השאלה — איך משלבים אותם?

נקודת המוצא המשותפת לכל הגישות

inputs = Input(shape=x_train.shape[1:])
conv1 = Conv2D(32, (3,3), padding='same', activation='relu')(inputs)
conv2 = Conv2D(32, (5,5), padding='same', activation='relu')(inputs)
  • conv1 — קרנל קטן (3×3): דפוסים מקומיים-צרים
  • conv2 — קרנל גדול (5×5): דפוסים מרחביים רחבים יותר
  • padding='same' שומר על אותו H×W בפלט

מכאן יש שלוש דרכים אפשריות להמשיך

  • גישה 1 — לשטח (Flatten) כל ענף בנפרד, ואז לחבר
  • גישה 2 — לחבר על ציר הערוצים, ולהישאר מרחבי
  • גישה 3 — לא להסתעף בכלל: לשרשר בטור (conv2 מקבל את פלט conv1)

מקבילי + Flatten מוקדם

כל ענף הופך לווקטור שטוח, ורק אז מתחברים

from tensorflow.keras.layers import Input, Conv2D, Flatten, Concatenate
from tensorflow.keras.models import Model

inputs = Input(shape=x_train.shape[1:])

conv1 = Conv2D(32, (3,3), padding='same', activation='relu')(inputs)
conv2 = Conv2D(32, (5,5), padding='same', activation='relu')(inputs)

# שטיחה של כל ענף בנפרד — לפני המיזוג
flat_input = Flatten()(inputs)
flat_conv1 = Flatten()(conv1)
flat_conv2 = Flatten()(conv2)

# חיבור על ציר הווקטורים (ברירת מחדל axis=1)
features = Concatenate()([flat_input, flat_conv1, flat_conv2])

גישה 1 — נקודת תורפה

למה ה-Flatten המוקדם בעייתי?

ה-Flatten הורג את הקשר הגיאומטרי בין תאים סמוכים — לפני שהוא בכלל נוצל

מה בדיוק נהרס

  • לפני Flatten: טנזור (H, W, C) — לכל תא יש "שכנים" ברורים
  • אחרי Flatten: וקטור ארוך — כל מיקום הוא סתם אינדקס, בלי משמעות מרחבית
  • שכבת Dense שתבוא אח״כ תצטרך "ללמוד מחדש" יחסים מרחביים מאפס, מתוך וקטור שטוח

מחיר נוסף — התנפחות

  • אורך features = H·W·C_in + H·W·32 + H·W·32
  • עבור לוח 8×8 עם כמה ערוצים — הווקטור יכול להגיע לאלפי איברים
  • שכבת Dense שאחריו — יקרה ורגישה יותר ל-overfitting

מה קורה כאשר עושים Flatten לפני Concatenate, בהשוואה למיזוג על ציר הערוצים?

💡 נכון! ב-Flatten כל תא הופך לאיבר בווקטור שטוח ומאבד את הזהות הגיאומטרית שלו. במיזוג axis=-1 הטנזור נשאר (H, W, C), ואפשר להמשיך לעבד אותו spatially (למשל עוד Conv2D) לפני שמוותרים על המבנה.

מקבילי + מיזוג במרחב

Concatenate על ציר הערוצים (axis=-1) — בלי Flatten מוקדם

from tensorflow.keras.layers import Input, Conv2D, Concatenate, Flatten, Dense, MaxPooling2D
from tensorflow.keras.models import Model

inputs = Input(shape=x_train.shape[1:])

conv1 = Conv2D(32, (3,3), padding='same', activation='relu')(inputs)
conv2 = Conv2D(32, (5,5), padding='same', activation='relu')(inputs)

# מיזוג על ציר הערוצים — הצורה נשארת (H, W, 64)
merged = Concatenate(axis=-1)([conv1, conv2])

# עכשיו אפשר להמשיך לעבד spatially!
x = Conv2D(64, (3,3), padding='same', activation='relu')(merged)
x = MaxPooling2D((2,2))(x)

# רק בסוף, אחרי שהמידע כבר עובד ומוזג — שוטחים
flat = Flatten()(x)
output = Dense(10, activation='softmax')(flat)

model = Model(inputs=inputs, outputs=output)

גישה 2 — למה זה עדיף

הדמיון למודול Inception

כמה קונבולוציות בגדלים שונים על אותו קלט, ואז מיזוג בציר הערוצים — בדיוק העיקרון מ-GoogLeNet

מה מרוויחים

  • המבנה המרחבי נשמר עד שלב מאוחר — אפשר עוד "לדעת" מי שכן של מי
  • שכבת Conv2D נוספת אחרי המיזוג יכולה לשלב בין מידע מ-3×3 ל-5×5 תוך ניצול סמיכות מרחבית
  • וקטור הפיצ'רים הסופי בד״כ קטן משמעותית, בעיקר עם MaxPooling2D
  • פחות פרמטרים ב-Dense ⇒ פחות סיכון ל-overfitting

אם רוצים לשמר גם את הלוח הגולמי (כמו ב-flat_input בגישה 1) — אפשר להוסיף אותו כערוץ נוסף: 

merged = Concatenate(axis=-1)([inputs, conv1, conv2])

בתנאי ש-inputs ו-conv1/conv2 חולקים אותו H×W — מובטח כאן הודות ל-padding='same'.

שרשור טורי

פלט conv1 הופך לקלט של conv2 — לא הסתעפות, אלא עומק

from tensorflow.keras.layers import Input, Conv2D
from tensorflow.keras.models import Model

inputs = Input(shape=x_train.shape[1:])

conv1 = Conv2D(32, (3,3), padding='same', activation='relu')(inputs)

# שימו לב: הקלט הוא conv1, לא inputs!
conv2 = Conv2D(32, (5,5), padding='same', activation='relu')(conv1)

# conv2 "רואה" גרסה שכבר סוננה ע"י conv1 —
# לא את הפיקסלים המקוריים

  • גישה 3 עונה: "איך בונים ייצוגים מורכבים יותר, שלב אחר שלב?" (עומק)

מחיר

  • conv2 לא רואה בכלל את הפיקסלים המקוריים — רק את מה ש-conv1 "החליט" להעביר אחרי ReLU
  • אם conv1 איפס מידע חשוב (ReLU) — conv2 לא יכול לשחזר אותו

מה למדנו
