יסודות

מהו משתנה?

משתנה הוא "תיבה" בזיכרון עם שם, שמחזיקה ערך שיכול להשתנות במהלך ריצת הסקריפט. ב-PowerShell כל משתנה מתחיל בסימן $.

$name = "דנה"
$age = 17
$isStudent = $true

Write-Host "$name בת $age"  # אינטרפולציה בתוך מחרוזת

שימו לב: PowerShell הוא dynamically typed — אין חובה להצהיר על טיפוס מראש, המשתנה "לומד" את הטיפוס מהערך שהוכנס אליו.

סוגי משתנים

משתנים מוצהרים וטיפוס, ומשתנים אוטומטיים

הצהרת טיפוס מפורשת

[int]$number = 5
[string]$text = "שלום"
[bool]$flag = $true
[double]$price = 19.99
[datetime]$date = Get-Date

אם מכניסים ערך שלא תואם את הטיפוס — PowerShell יזרוק שגיאה או ינסה להמיר.

משתנים אוטומטיים (Automatic)

קיימים תמיד, ה-runtime ממלא אותם עבורנו:

$_  # האובייקט הנוכחי בצנרת
$args  # ארגומנטים שהועברו לפונקציה
$true / $false / $null
$LASTEXITCODE
$PWD  # תיקיית העבודה הנוכחית
Set-Variable -Name "PI" -Value 3.14159 -Option Constant
Set-Variable -Name "MAX" -Value 100 -Option ReadOnly
תחום תוקף

Scope — איפה המשתנה "חי"?

תחום התוקף קובע מאיפה בקוד נגישים למשתנה. זו אחת הנקודות שהכי מבלבלות מתכנתים מתחילים — ובצדק.

Scopeתחום נגישותתחביר
Local (ברירת מחדל)בתוך הבלוק/פונקציה בלבד$x
Scriptכל הסקריפט הנוכחי$script:x
Globalכל הסשן, כולל מודולים אחרים$global:x
Privateאפילו לא ל-child scopes$private:x
הדגמה

Local מול Global, ו-Shadowing

$x = "גלובלי"

function Show-X {
    $x = "מקומי"   # local חדש, מסתיר את הגלובלי
    Write-Host $x          # מדפיס: מקומי
}

Show-X
Write-Host $x              # מדפיס: גלובלי — לא השתנה!
מה יודפס בשורה האחרונה אם בפונקציה נשתמש ב-$global:x = "מקומי" במקום $x = "מקומי"?
גלובלי — הפונקציה לא באמת משנה כלום
מקומי — כי עכשיו אנחנו כותבים במפורש למשתנה הגלובלי
שגיאה — אי אפשר לשנות global מתוך פונקציה
משתני סביבה

Environment Variables — $env:

אלה לא קשורים ל-scope שראינו קודם — הם מגיעים ממערכת ההפעלה ונגישים לכל תהליך, לא רק ל-PowerShell.

$env:USERNAME
$env:COMPUTERNAME
$env:PATH

Get-ChildItem Env:              # הצגת כולם
$env:MY_VAR = "ערך לדוגמה"    # יצירה/שינוי לתהליך הנוכחי בלבד

שינוי ב-$env: לא נשמר אחרי סגירת הסשן. לשינוי קבוע:

[Environment]::SetEnvironmentVariable("MY_VAR", "ערך", "User")
[Environment]::SetEnvironmentVariable("MY_VAR", "ערך", "Machine")  # דורש הרשאות מנהל
⏸ תחנת עצירה

עכשיו אתם

כתבו סקריפט קצר שמדגים shadowing: משתנה גלובלי בשם $counter, ופונקציה שמנסה לשנות אותו — פעם אחת עם משתנה local, ופעם אחת עם $script:counter. הריצו והשוו תוצאות.

זמן: כ-5 דקות. אני אעבור ביניכם.

קלט

פעולות קלט (Input)

מהמשתמש

$name = Read-Host "הזן שם"
$pw = Read-Host "סיסמה" -AsSecureString
[int]$age = Read-Host "הזן גיל"

מקבצים / מהסקריפט

param(
    [string]$Name,
    [int]$Age
)

$content = Get-Content "file.txt"
$data = Import-Csv "data.csv"
פלט

פעולות פלט (Output)

Write-Host "טקסט למסך"          # ישיר למסך, לא ניתן ללכוד
Write-Output "ערך"              # לצנרת (pipeline) — ברירת מחדל
Write-Warning "אזהרה"
Write-Error "שגיאה"

$data | Format-Table
$data | Export-Csv "out.csv" -NoTypeInformation
מה ההבדל המרכזי בין Write-Host ל-Write-Output?
אין הבדל אמיתי, זה עניין של סגנון
Write-Host כותב ישירות למסך ולא ניתן ללכוד את הפלט; Write-Output נכנס לצנרת וניתן להעביר הלאה
Write-Host עובד רק עם מספרים
בקרה

תנאים: if / switch / טרנרי

if / elseif / else

if ($x -gt 10) {
    "גדול"
} elseif ($x -eq 10) {
    "שווה"
} else {
    "קטן"
}

switch וטרנרי

switch ($day) {
    1 { "ראשון" }
    2 { "שני" }
    default { "לא ידוע" }
}

# PowerShell 7+
$result = $x -gt 10 ? "גדול" : "קטן"

שימו לב — לא == אלא: -eq -ne -gt -ge -lt -le. לוגי: -and -or -not

לולאות

for / while / do

for — כשיודעים כמה איטרציות

for ($i = 1; $i -le 10; $i++) {
    $i
}

while — כל עוד תנאי מתקיים

$i = 1
while ($i -le 10) {
    $i; $i++
}

do-while / do-until — לפחות פעם אחת

do {
    $i++
} while ($i -le 10)

do {
    $i++
} until ($i -gt 10)

ההבדל מ-while: הגוף רץ לפחות פעם אחת, גם אם התנאי כוזב מהתחלה.

לולאות

foreach, ForEach-Object, ושליטה בלולאה

מעבר על אוסף

foreach ($item in $array) {
    $item
}

# גרסת pipeline
1..10 | ForEach-Object { $_ * 2 }

break / continue

foreach ($n in 1..20) {
    if ($n -eq 15) { break }
    if ($n % 2 -eq 0) { continue }
    $n
}
